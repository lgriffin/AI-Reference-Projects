Work in your copy, `/tmp/my-course-up`, never in the clone.

## 1. One program, many tools

~~~bash
cd /tmp/my-course-up
deno run -A $MONO/packages/jsr/tutors-cli/main.ts help
~~~

~~~
Usage: tutors <command>

  build       build the course in this folder into json/ for the Tutors reader (@tutors/tutors)
  website     build the course in this folder into html/, a website of its own (@tutors/tutors-lite)
  validate    check a course folder: tutors validate [folder] [--format text|json|sarif] [--strict] [--fix]
  import      propose a course from a folder of material: tutors import <folder> --name <course name>
  ...
~~~

Open `packages/jsr/tutors-cli/main.ts`. `build` is one line: `await import("@tutors/tutors")`, which runs
`packages/jsr/tutors/main.ts`. Compare that file with `variants/rung-1-seed/src/main.ts`.

## 3. A crash worth reporting

~~~bash
cd /tmp/my-course-up && rm -rf json properties.yaml
deno run -A $MONO/packages/jsr/tutors-cli/main.ts build
~~~

~~~
: my-course-up : My First Course
--: topic-01-hello : Hello
----: note-1-welcome : Welcome
----: web-1-tutors : Tutors
error: Uncaught (in promise) TypeError: Cannot read properties of undefined (reading 'llm')
~~~

`ls json` shows `tutors.json` was written before the crash. Find `generateLlms` in
`packages/jsr/gen/src/utils/llms.ts` and the line that reads `course.properties.llm`. Now validate:

~~~bash
deno run -A $MONO/packages/jsr/tutors-cli/main.ts validate
~~~

~~~
warn  V011 netlify.toml: This course has no netlify.toml, so Netlify won't know how to build and publish it. Add the standard one (tutors validate --fix writes it).
0 errors, 1 warning.
~~~

The validator says the course is fine; the generator crashes on it. Rung 1 reads no properties, so it cannot
crash here. This mismatch between two readers of the same format is the kind of finding week 12 turns into a
first upstream issue. Write it down.
