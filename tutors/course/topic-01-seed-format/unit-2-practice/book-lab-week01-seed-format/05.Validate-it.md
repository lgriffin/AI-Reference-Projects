# Validate it (Apply, Analyse)

The module keeps one command that says "this is a compliant Tutors course":
`tutors/scripts/check-course.sh`. It is a Single Gate for course content.

~~~bash
cd ~/src/AI-Reference-Projects
TUTORS_MONO_REPO=$MONO tutors/scripts/check-course.sh ~/src/my-course
~~~

If `deno` is not on your `PATH`, add `DENO=/path/to/deno` in front. The first run downloads the generator's
packages from JSR.

## What you should see

~~~
== validate (/home/you/src/my-course)
warn  V011 netlify.toml: This course has no netlify.toml, so Netlify won't know how to build and publish it. Add the standard one (tutors validate --fix writes it).
0 errors, 1 warning.
It can be fixed for you: run tutors validate --fix.
== build
----: note-1-welcome : Welcome
----: web-1-tutors : Tutors
tutors: 5.3.0
OK: compliant course, 1408 bytes of tutors.json
~~~

## What the script does

It does not carry its own copy of the Tutors rules. It uses the real ones from your clone:

1. It copies your course into a temporary folder, so your folder is never changed.
2. It runs `packages/jsr/tutors-cli/main.ts validate` from `$TUTORS_MONO_REPO` with Deno. That applies the
   rules in `packages/jsr/course-rules` (V001 to V021, catalogued in `src/finding.ts`).
3. If there are no errors, it runs the same CLI's `build`, which calls the real generator, and checks that
   `json/tutors.json` was written.

Zero errors: your course is compliant. The V011 warning is fair; `netlify.toml` tells Netlify how to publish
the course, and you can add it later.

## Break it on purpose

Rename the note's folder so its name has no kind, and run the script again:

~~~bash
mv ~/src/my-course/topic-01-hello/note-1-welcome ~/src/my-course/topic-01-hello/welcome
TUTORS_MONO_REPO=$MONO tutors/scripts/check-course.sh ~/src/my-course; echo "exit $?"
~~~

~~~
== validate (/home/you/src/my-course)
error V002 topic-01-hello/welcome: The folder "welcome" won't appear in your course, nor will anything inside it, because its name doesn't start with a kind Tutors knows (topic, unit, talk, note, lab and so on). Rename it so it starts with the kind of content it holds, like talk-, note- or lab-.
warn  V011 netlify.toml: This course has no netlify.toml, so Netlify won't know how to build and publish it. Add the standard one (tutors validate --fix writes it).
1 error, 1 warning. Fix the errors before publishing.
1 of these can be fixed for you: run tutors validate --fix.
validate: errors found
exit 1
~~~

The message names the rule (V002), the offender (`welcome`) and the fix. That is level **L4, Explained**.
Put the name back before you go on:

~~~bash
mv ~/src/my-course/topic-01-hello/welcome ~/src/my-course/topic-01-hello/note-1-welcome
~~~

## Check yourself

The generator would have built the broken course without a word, leaving the note out. At which level of the
Assertion Ladder does the *generator* keep the naming rule, and at which does the *validator*?
