# Kaizen (Evaluate)

Every lab ends with a short Kaizen step: a small, continuous improvement to the way the work is done. Ten
minutes, in your notes.

## 1. Name one waste

Look back over today. Pick one waste you met, in the course format, in the tools, or in your own way of
working. The common wastes of software work:

| Waste | What it looked like today, perhaps |
| --- | --- |
| Defects | a misnamed folder that vanished without a word |
| Delays and waiting | the first `deno run` downloading packages |
| Relearning | looking up the same command twice |
| Task switching | moving between three repositories and two runtimes |
| Partially done work | a course that builds but does not validate |
| Extra features | an idea that is not needed yet, which the Rung Fence would refuse |

## 2. Find its root cause

Ask "why?" until you reach something you could change. One or two whys are enough this week; week 5 teaches
Five Whys properly.

## 3. Propose one improvement to the standard work

Today's standard work is: write the course, run `check-course.sh`, run the generator, read the output. Make
one change that removes the waste you named. For example: put `LADDER` and `MONO` in your shell profile so
you never relearn them; keep a `~/ladder-tools/` folder for scripts you will reuse; add `json/` and `out/` to
your course's `.gitignore`.

Write it as one sentence: "I will ... so that ...". Make the change if it is yours to make.
