# A URL that names nothing (Analyse)

A reader is judged as much by its wrong turns as by its pages. Try each of these in the address bar.

| URL | What you see |
| --- | --- |
| `/course/nope` | 404, `Not found: the course "nope"` |
| `/topic/ladder-sample-course/no-such-topic` | 404, `Not found: a topic at /topic/ladder-sample-course/no-such-topic` |
| `/talk/ladder-sample-course/topic-01-basics/unit-1-intro/note-1-reading` | 404, `Not found: a talk at ...` |
| `/lab/ladder-sample-course/topic-02-practice/unit-1-lab/book-1-first-lab/Nope` | 404, `Not found: a lab step at ...` |

## Trace the first one

`/course/nope` is the interesting one. Watch the Network tab while you load it: the request for
`/courses/nope/tutors.json` answers **200**, with HTML. The dev server, like a static host, answers a
missing file with the app's fallback page.

Find, in `lib/course/course-service.ts`:

1. the line that survives an answer that is not JSON;
2. the function that decides the answer is not a course;
3. the function that writes the message.

Then find the three scenarios under R-016 in `reader.feature`. Which one is the case you just saw?

## Trace the third one

The third URL names a real page: the note exists. Why is it a 404? Find the comparison in `requestLo` that
decides it. Without that comparison, what would the talk route show?

## A lab step

Open
<http://localhost:5173/lab/ladder-sample-course/topic-02-practice/unit-1-lab/book-1-first-lab/Setup>.

| File | What happens |
| --- | --- |
| `routes/(course-reader)/lab/[courseid]/[...loid]/+page.ts` | calls `requestLab` with the whole path |
| `lib/course/course-service.ts`, `readLab` | the path is not a lab, so it cuts the last segment (`Setup`) and looks up the rest |
| `lib/course/live-lab.ts`, `liveLab(lab, "Setup")` | the step, its index and its neighbours, as plain data (R-019) |
| `lib/ui-components/content/lab/Lab.svelte` | the step list, the step's Markdown, the pager |

Remove `/Setup` from the address. You get step 1: the path **is** a lab, so `liveLab(lab)` opens its first
step (R-018).

## Where does the 404 become a 404?

Open `routes/(course-reader)/found.ts`. Then list every reader file that uses SvelteKit:

~~~bash
grep -rl "@sveltejs/kit\|\$app/" apps/reader/src
~~~

~~~
apps/reader/src/lib/ui-components/content/lab/Lab.svelte
apps/reader/src/routes/(course-reader)/+layout.svelte
apps/reader/src/routes/(course-reader)/found.ts
apps/reader/src/routes/+error.svelte
~~~

Nothing in `lib/course`. The course service answers `{ notFound: "..." }` and knows nothing about
SvelteKit; `found` turns the message into `error(404, ...)`; `+error.svelte` shows it.
