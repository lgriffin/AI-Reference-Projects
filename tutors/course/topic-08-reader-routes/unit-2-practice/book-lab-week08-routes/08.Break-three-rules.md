# Break three rules (Analyse)

Each break takes one line. Make the change, run the command, read the failure, then undo it with
`git checkout .` (and `git clean -fd apps` after the second). Before each run, predict which test will
fail.

## 1. A route that fetches

In your new `wall/[type]/[courseid]/+page.ts`, add as the first line of the load:

~~~ts
  await fetch(`/courses/${params.courseid}/tutors.json`);
~~~

It looks harmless: the route is "warming the cache".

~~~bash
pnpm exec vitest run tests/architecture
~~~

~~~
AssertionError: Loader rule: the reader reaches the network in one place, lib/course/course-service.ts,
which fetches tutors.json with the fetch a load function hands it and keeps the course. Upstream's
courseService does the same. Call readCourse, readLo or readLab from the route's +page.ts.
  apps/reader/src/routes/(course-reader)/wall/[type]/[courseid]/+page.ts
~~~

Which requirement would this line have broken, silently, with every test still green? (Count the
requests.)

## 2. A server load

Create `apps/reader/src/routes/(course-reader)/+layout.server.ts` holding one line:

~~~ts

~~~

~~~bash
pnpm exec vitest run tests/rung-fence.test.ts
~~~

~~~
AssertionError: Rung Fence, rung 5 (Reader): apps/reader/src/routes/(course-reader)/+layout.server.ts is
server code. The reader is a static build (adapter-static, ssr = false): every load runs in the browser.
Upstream's server routes serve sign-in and learning records, which arrive with identity in rung 6

Lifting the fence is a person's decision: see AGENTS.md, "Ask a human first".

This is the file a coding agent trained on older SvelteKit examples is most likely to add. The fence names
the rung where it would belong.

## 3. SvelteKit in the logic

As the first line of `apps/reader/src/lib/course/live-lab.ts`, add:

~~~ts
import { error } from "@sveltejs/kit";
~~~

It is the first move of "let the logic throw the 404 itself".

~~~bash
pnpm exec vitest run tests/architecture
~~~

~~~
AssertionError: Framework rule: lib/course does not use SvelteKit, because course turns tutors.json into a
tree and finds pages in it; it is plain TypeScript, so Vitest runs it without a browser and Stryker can
mutate it. Take what SvelteKit gives (fetch, params, navigation) as an argument from a route.
  apps/reader/src/lib/course/live-lab.ts imports "@sveltejs/kit"
~~~
