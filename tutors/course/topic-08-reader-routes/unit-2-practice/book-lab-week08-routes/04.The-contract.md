# The contract (Understand, Analyse)

`pnpm dev` and `pnpm build` both start with `pnpm course`. Run it by itself in a second terminal:

~~~bash
pnpm course
~~~

~~~
wrote 0 pages and tutors.json to .../rung-5-reader/apps/reader/static/courses/ladder-sample-course
~~~

That is rung 4's command with one new flag, `--json-only` (R-013, in `apps/cli/src/run.ts`). Zero pages:
the reader needs only the contract. The reader serves `apps/reader/static` as files, so this file becomes
`/courses/ladder-sample-course/tutors.json`. Open
<http://localhost:5173/courses/ladder-sample-course/tutors.json> and see it.

## Look inside

~~~bash
node -e '
const c = require("./apps/reader/static/courses/ladder-sample-course/tutors.json");
const walk = (lo, d) => { console.log("  ".repeat(d) + lo.type.padEnd(8) + lo.route); (lo.los ?? []).forEach((l) => walk(l, d + 1)); };
walk(c, 0);'
~~~

~~~
course  /
  topic   /topic/{{COURSEURL}}/topic-01-basics
    unit    /topic/{{COURSEURL}}/topic-01-basics/
      talk    /talk/{{COURSEURL}}/topic-01-basics/unit-1-intro/talk-1-welcome
      note    /note/{{COURSEURL}}/topic-01-basics/unit-1-intro/note-1-reading
    side    /topic/{{COURSEURL}}/topic-01-basics/
      archive /archive/{{COURSEURL}}/topic-01-basics/side-resources/archive-1-solutions
  topic   /topic/{{COURSEURL}}/topic-02-practice
    unit    /topic/{{COURSEURL}}/topic-02-practice/
      lab     /lab/{{COURSEURL}}/topic-02-practice/unit-1-lab/book-1-first-lab
        step    /lab/{{COURSEURL}}/topic-02-practice/unit-1-lab/book-1-first-lab/Lab-01-First-Steps
        step    /lab/{{COURSEURL}}/topic-02-practice/unit-1-lab/book-1-first-lab/Setup
        step    /lab/{{COURSEURL}}/topic-02-practice/unit-1-lab/book-1-first-lab/Build
      web     https://tutors.dev
~~~

Three things to notice:

- every route holds `{{COURSEURL}}`. The reader fills it in, because only the reader knows which id the
  course was opened with (R-017);
- a unit's route is its topic's route with a trailing slash. A unit has no page of its own;
- the first segment of each route (`topic`, `talk`, `note`, `lab`) is the name of a folder under
  `apps/reader/src/routes/(course-reader)/`. The contract and the router agree by name.

## Compare with upstream's file

The file upstream's generator wrote for the same course sits at `../fixtures/ladder-sample-course.tutors.json`.
Run the same walk on it (change the `require` path). The output is identical. Then compare the fields:

~~~bash
node -e '
const keys = (f) => Object.keys(require(f)).sort().join(" ");
console.log("ours    :", keys("./apps/reader/static/courses/ladder-sample-course/tutors.json"));
console.log("upstream:", keys("../fixtures/ladder-sample-course.tutors.json"));'
~~~

~~~
ours    : contentMd id los route summary title type
upstream: authLevel contentMd frontMatter hide id img imgFile los properties route summary title type video videoids
~~~

Upstream's file has more. The reader ignores what it does not use.

## Who reads which file?

~~~bash
grep -rln "ORACLE" tests/unit/reader tests/bdd/support tests/conformance
~~~

~~~
tests/unit/reader/lo-tree.test.ts
tests/unit/reader/course-service.test.ts
tests/bdd/support/reader.ts
tests/conformance/tutors-json.test.ts
~~~

`ORACLE` is upstream's file. The reader's unit tests and scenarios read **it**, not the one `pnpm course`
wrote. The conformance test compares our generator with it. So the reader is proved against the contract as
upstream writes it, and the generator is proved to write it.
