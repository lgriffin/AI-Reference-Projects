# Hints

One at a time. Try for ten minutes before you take the next.

## Hint 1: two lines decide

Every other block in `renderMarkdown` is recognised from its first line. A table needs two: a header row is
just text until the next line turns out to be a delimiter row. So the branch's condition looks at `line`
and at `lines[i + 1]`.

## Hint 2: one helper for every row

Write `cells(line)`: trim the line, remove one leading `|` and one trailing `|`, split on `|`, trim each
part. The header, the delimiter row and every body row go through it.

## Hint 3: the delimiter row

A delimiter cell matches `/^:?-+:?$/`. Read the alignment from the colons: both ends is center, the right
end only is right, the left end only is left, none is no style. Return `null` when the line is not a
delimiter row, so the caller can fall through to the paragraph.

## Hint 4: one cell, one rule

Render a cell with `renderInline(text)`, never with the text itself. Then a `<` in a cell is escaped and
`` `code` `` in a cell is a code span, for free. Give each `<th>` and `<td>` the same alignment as its column,
and use `row[i] ?? ""` for a missing cell.

## Hint 5: where the table ends

After the delimiter row, consume lines while they are not blank and contain a `|`. Leave `i` at the first
line you did not consume, as every other branch does, so a paragraph after the table is still rendered.

## Hint 6: the order of the branches

Put the table branch before the heading branch, or at least before the paragraph branch. Why must it be
before the paragraph? What would happen to a header row otherwise?
