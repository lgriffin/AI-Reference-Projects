# Escaping, side by side (Analyse)

Add raw HTML to the note in your upstream copy:

~~~bash
cd /tmp/ladder-fixture
cat >> topic-01-basics/unit-1-intro/note-1-reading/note.md <<'MD'

<script>alert("from the note")</script>

A title with <b>bold</b> tags.
MD
deno run -A $MONO/packages/jsr/tutors-cli/main.ts website
grep -o '<script>alert[^<]*</script>' html/topic-01-basics/unit-1-intro/note-1-reading/index.html
grep -o 'with <b>bold</b>' html/topic-01-basics/unit-1-intro/note-1-reading/index.html
~~~

~~~
<script>alert("from the note")</script>
with <b>bold</b>
~~~

Both tags reach upstream's page as markup. Open the page: the alert runs.

Now build the same folder with rung 2:

~~~bash
cd $LITE
node src/main.ts /tmp/ladder-fixture out-evil
grep -o '&lt;script&gt;alert[^<]*' out-evil/topic-01-basics/unit-1-intro/note-1-reading/index.html
~~~

~~~
&lt;script&gt;alert(&quot;from the note&quot;)&lt;/script&gt;
~~~

Open that page: the script and the bold tag are shown as text. No alert.

## Why they differ

Find these two settings upstream:

- `html: true` in `packages/jsr/model/src/utils/markdown-utils.ts`
- `autoescape: false` in `packages/jsr/gen/src/templates/template-engine.ts`

Neither is a mistake on its own: lecturers use raw HTML in notes. Write two sentences on what each choice
gives and what it costs. Rung 6 (Guarded, week 10) shows how the reader sanitises instead. Delete `out-evil/`.
