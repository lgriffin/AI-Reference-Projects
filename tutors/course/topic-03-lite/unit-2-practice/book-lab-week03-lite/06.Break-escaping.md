# Break escaping on purpose (Analyse)

In `src/site-builder.ts`, take a shortcut that an agent in a hurry might take. Change the import of
`SafeHtml` from a type import to a value import:

~~~ts
import { html, page, SafeHtml } from "./html.ts";
~~~

(and delete the `import type { SafeHtml }` line), then make the archive card build its heading by hand:

~~~ts
    case "archive":
      return html`<li class="card">${kind}${new SafeHtml(`<h3>${lo.title}</h3>`)}<p>${lo.summary}</p><p><code>${lo.archiveFile}</code></p></li>`;
~~~

Run the gate:

~~~bash
npm test
~~~

~~~
not ok 11 - only html.ts and markdown.ts make SafeHtml, because only they escape what they wrap
    Trusted HTML rule: `new SafeHtml(...)` skips escaping, so it may appear only in src/html.ts and src/markdown.ts. Build the HTML with the html`` template instead; it escapes every value for you.
not ok 21 - course text never reaches a page unescaped
  error: 't/index.html contains an unescaped <script>'
# pass 20
# fail 2
~~~

Two levels caught one shortcut:

| Test | Level | What it knows |
| --- | --- | --- |
| Trusted HTML rule | L4 | **where** escaping may be skipped; its message names the fix |
| course text never reaches a page unescaped | L3 | **that** a page holds a raw tag, and which page |

The first would catch the shortcut even if the escaping test had no archive case. The second would catch
an unescaped field even if it got there some other way. Restore the file with `git checkout src/site-builder.ts`.
