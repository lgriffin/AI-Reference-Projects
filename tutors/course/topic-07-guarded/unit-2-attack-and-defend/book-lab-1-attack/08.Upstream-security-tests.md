# Experiment on upstream

Now see the same ideas at full scale in tutors-mono-repo (Node 26.13 or later, installed in Lab 01).

## Sanitising Marp slides

Open `tests/unit/reader/marp-slides.test.ts`. Find "drops executable URLs from links, images and SVG, and
active embedded documents". Compare its payloads with rung 6's corpus: which does upstream have that rung 6
does not (`xlink:href`, `srcdoc`, `formaction`)? Why does upstream need them? (Hint: Marp passes raw HTML
through, and `packages/svelte/ui-primitives/src/utils/sanitize.ts` runs DOMPurify over the result.)

## The course rule for scripts in slides

Open `packages/jsr/course-rules/src/rich.ts` and find `STRIPPED`. Then open
`tests/unit/course-rules/course-rich.test.ts`, "names each slide with something the reader strips". This is
the author-facing warning (V016) for what the reader's sanitiser will remove.

## Security contracts

Open `tests/security/security.test.ts`, `tests/security/header-contract.json` and
`tests/security/known-response-gaps.txt`. Run them:

~~~bash
cd tutors-mono-repo
pnpm vitest run tests/security tests/unit/course-rules/course-rich.test.ts tests/unit/rbac/lock-matching.test.ts
~~~

Every file passes. Now answer:

1. Which header does every app still not send, and why does the gaps file say a policy "is not guessed here"?
2. `audit-allowlist.json` is empty. What two fields must an allowance have, and what happens when one expires?
3. In `lock-matching.test.ts`, why does a lock on `/topic/cs101` lock nothing? (You will need this for the
   assignment.)

## The supply-chain workflows

Read `.github/workflows/codeql.yml`, `zizmor.yml` and `scorecard.yml`. Each starts with `permissions: {}`.
Which job permissions does each grant, and why does each pin its actions by commit SHA with the version in a
comment? Then read `docs/security/scorecard-baseline.md`: which check would you fix first, and why?
