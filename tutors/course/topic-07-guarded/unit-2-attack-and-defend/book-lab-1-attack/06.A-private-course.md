# A private course

A course with `auth: 1` in `properties.yaml` is for signed-in, enrolled readers only (upstream
`guides/RBAC.md`, "Auth Levels"). A static site has no sign-in.

~~~bash
mkdir -p $LAB/private && cd $LAB/private
printf '# Private course\n\nFor enrolled readers.\n' > course.md
printf 'auth: 1\n' > properties.yaml
printf 'educators:\n  - your-github-login\nwhitelist:\n  - a-student\n' > enrollment.yaml
cd -
pnpm start $LAB/private $LAB/rung-6-private; echo "exit $?"
~~~

~~~
/tmp/.../private is a private course (properties.yaml says auth: 1), so the reader shows it only to signed-in, enrolled readers (sign-in-required). A static site has no sign-in: anyone with its link could read it. Nothing was written. To build it for a host that adds its own access control, run again with --private; every page is then marked private and noindex.
exit 1
~~~

Build it on purpose, and look at what changes:

~~~bash
pnpm start $LAB/private $LAB/rung-6-private --private
~~~

~~~
wrote 1 pages, marked private, and tutors.json to /tmp/.../rung-6-private
~~~

~~~bash
grep -o '<meta name="robots"[^>]*><meta name="tutors-access"[^>]*>' $LAB/rung-6-private/index.html
~~~

Now read the decision. `apps/cli/src/run.ts` asks `canView` in `packages/rbac/src/index.ts` about an
anonymous reader (`AnonymousSession`). Open `packages/rbac/tests/policy.test.ts`: the whole policy is one
table. Change `auth: 1` to `auth: yes` and build again without `--private`. The message now says
`properties.yaml says auth: yes`. Why is it still refused? Find `accessOf`, and the two words for this
behaviour in its comment.
