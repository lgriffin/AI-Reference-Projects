# Read outside the course

The generator runs as you. Make a copy of the hostile course whose `course.md` is a symbolic link to a
"private" file of yours that lives outside the course:

~~~bash
cp -r ../rung-6-guarded/tests/fixtures/hostile-course $LAB/linked
mkdir -p $LAB/home && printf '# My private notes\n\nThe exam answers are 42.\n' > $LAB/home/notes.md
rm $LAB/linked/course.md
ln -s $LAB/home/notes.md $LAB/linked/course.md
~~~

(On Windows, use WSL for this step, or skip to the next and read the contract test instead.)

Build it with rung 3:

~~~bash
node apps/cli/src/main.ts $LAB/linked $LAB/rung-3-linked
grep -o '<h1>[^<]*</h1>\|The exam[^<]*' $LAB/rung-3-linked/index.html
~~~

~~~
<h1>My private notes</h1>
The exam answers are 42.
~~~

Your private file is now the course's home page, and in `tutors.json`. Rung 3's `NodeFileSystem` does skip
links when it lists a folder, but `course.md` is never listed: the generator asks for it by name, and
`readFile` follows the link.

## The other leak: links on a page

`note-1-links/note.md` links to `../../../answers/solutions.md`, and lab step `01.Next.md` shows
`../../../../../etc/passwd` as an image. Neither file is copied, but the links point readers, and anyone who
copies the topic into another course, at places the author never meant to share. Rung 3 says nothing.
