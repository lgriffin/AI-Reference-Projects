# The last wall: CSP

Suppose a future change to lite lets a script through. The Content Security Policy is still there. Look at
the head of any rung 6 page:

~~~bash
head -4 $LAB/rung-6/index.html
~~~

~~~html
<!doctype html>
<html lang="en">
<head><meta charset="utf-8">
<meta http-equiv="Content-Security-Policy" content="default-src &#39;none&#39;; img-src &#39;self&#39; https:; style-src &#39;sha256-...&#39;; base-uri &#39;none&#39;; form-action &#39;none&#39;">
~~~

Now play the attacker who got past escaping and sanitising. Inject script by hand:

~~~bash
sed 's#<main>#<main><script>alert("injected")</script><a id="j" href="javascript:alert(2)">j</a>#' \
  $LAB/rung-6/index.html > $LAB/rung-6/injected.html
~~~

Open `$LAB/rung-6/injected.html`, open the developer tools console, and click **j**. No alert. The console says:

~~~
Executing inline script violates the following Content Security Policy directive 'default-src 'none''. ...
Running the JavaScript URL violates the following Content Security Policy directive 'default-src 'none''. ...
~~~

The page is still styled: its one inline style is allowed by its SHA-256 hash. Open
`packages/lite/tests/csp.test.ts` and find the test that keeps the hash honest. Change one character of
`STYLE` in `packages/lite/src/html.ts`, run `pnpm test`, and read the message: it gives you the new hash to
paste, and tells you never to reach for `'unsafe-inline'`. Undo the change.
