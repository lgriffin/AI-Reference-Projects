# The grading test

It is already in the variant: `tests/assignment/guarded.assignment.test.ts`. Read it before you write any
code; it is the specification. Three things to notice:

- **It is skipped by default.** Each `describe` has `{ skip }`, set from `LADDER_ASSIGNMENT`, so the
  variant's gate stays green until you start. `pnpm test:assignment` sets the variable.
- **It imports your code dynamically.** `rawHtmlFindings` does not exist yet, so a static import would fail
  the whole file. The helpers `gen()` and `rbac()` import the package and fail with AC1, AC5 or AC7 if the
  function is missing.
- **Every failure names its criterion.** For example:

~~~
AC2: rawHtmlFindings should return ["form","input"]: each HTML element's lower-case name once, in order of first appearance.
AC6: normalise with a loop, as upstream normalizeRoute does (CodeQL js/polynomial-redos).
~~~

## Grade it

~~~bash
pnpm test:assignment
~~~

~~~
# tests 31
# pass 31
# fail 0
~~~

Then remove the skip and run the Single Gate:

~~~bash
pnpm test
~~~

## Add your own tests

The grading test is the minimum. Add at least:

- three rows to `packages/lite/tests/xss-corpus.test.ts`'s `HOSTILE_TEXT`, and check that `rawHtmlFindings`
  reports each of them (an XSS corpus test for your rule);
- a table test for `canSeeLo` in `packages/rbac/tests/policy.test.ts`, every role against a locked route,
  a descendant, a sibling and an unlocked entry (RBAC policy tests).
