# Hints

Try each hint only when the one before it is not enough.

## Part A

1. Start from `prose()` in `packages/gen/src/portable.ts`: it already removes fenced and inline code.
2. A raw tag starts `<`, then a letter, then letters or digits, then a space, `/` or `>`. A lookahead,
   `(?=[\s/>])`, keeps `<hello@tutors.dev>` out.
3. `Array<string>` still matches hint 2. Keep a `Set` of HTML element names (`iframe`, `script`, `object`,
   `embed`, `form`, `input`, `svg`, `img`, `style`, `a`, `meta`, `b`, `div`, `span`, ...) and report only
   those. Upstream's V016 takes the other road: it looks only for what the sanitiser strips (`STRIPPED` in
   `packages/jsr/course-rules/src/rich.ts`). Which is better for authors?
4. Call it where `warnOutside` is called in `buildLo`, but for every kind, not only those outside `STAYS`.

## Part B

1. Read upstream's `isLoRouteLocked` and `normalizeRoute` in
   `packages/svelte/utils/rbac/src/rbac-service.svelte.ts`. Port the logic, not the runes.
2. Compare paths **after the type segment**: `/lab/cs101/week-01/lab-03` and `/topic/cs101/week-01` share
   `cs101/week-01`. A lock path needs at least two segments (course id and one more).
3. `path.startsWith(lockPath)` matches `week-010` under `week-01`. Compare with `` `${lockPath}/` ``.
4. Trailing slashes: a loop from the end, not `/\/+$/`. Upstream's comment says why (CodeQL
   `js/polynomial-redos`). The Purity rule allows a `let` inside a function, not at the top of the module.
