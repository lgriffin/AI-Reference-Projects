# Tools

You need four tools. The versions come from the mono-repo itself, so check them there when you are unsure.

| Tool | Version | Why | Where the version is pinned |
| --- | --- | --- | --- |
| Git | any recent | to clone the repositories | - |
| Node.js | 26.13.0 or later | the mono-repo's apps and tests | `engines` in `package.json`, and `.nvmrc` |
| pnpm | 11.24.0 | the mono-repo's package manager | `packageManager` in `package.json` |
| Deno | 2.9.6 | the generator, the validator and everything in `packages/jsr/` | `.dvmrc` |

The ladder's own variants need only Node.js 22.18 or later, because they run TypeScript with Node's built-in
type stripping. Node.js 26.13.0 satisfies both, so install that once.

## Node.js

The easiest route is a version manager such as [nvm](https://github.com/nvm-sh/nvm) (macOS, Linux, WSL) or
[nvm-windows](https://github.com/coreybutler/nvm-windows). With nvm, once you have cloned the mono-repo (next
step), `nvm install` in its folder reads `.nvmrc` and installs the pinned version.

~~~bash
node --version   # v26.13.0 or later
~~~

## pnpm

Do not install pnpm yet. The mono-repo's quick start installs the exact version its `package.json` pins, in
the next step. An older global pnpm may refuse to install the workspace (CONTRIBUTING.md says so).

## Deno

Follow the instructions at [deno.com](https://deno.com/), then check the version:

~~~bash
deno --version   # deno 2.x; the mono-repo pins 2.9.6 in .dvmrc
~~~

## Optional: kubectl or kustomize

The mono-repo's `pnpm test` includes three platform conformance tests that render the Kubernetes overlays in
`deploy/k8s`. They fail without `kubectl` or `kustomize` on your `PATH` ("Install kustomize or kubectl"). You
do not need them for this lab. You will at the Summit.
