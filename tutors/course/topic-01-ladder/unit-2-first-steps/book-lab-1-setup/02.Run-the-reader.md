# Run the real reader

Follow the quick start in the mono-repo's `README.md`. It is six commands:

~~~bash
git clone https://github.com/tutors-sdk/tutors-mono-repo.git
cd tutors-mono-repo
npm install --global "$(node -p "require('./package.json').packageManager")"
pnpm install
cp .env.example .env
pnpm dev
~~~

Then open **http://localhost:5173/course/reference-course**.

## What just happened

- The third command reads `packageManager` from `package.json` (`pnpm@11.24.0`) and installs exactly that
  version.
- `pnpm install` resolves the whole workspace. CONTRIBUTING.md warns it is large: over 800 MB of
  `node_modules`. A warning that it cannot create the `vitest-cucumber` bin is harmless.
- The copied `.env` has `PUBLIC_ANON_MODE=TRUE`. That turns off authentication, presence and analytics, so
  you need no Supabase project and no GitHub OAuth app.
- `pnpm dev` builds `ui-primitives`, `ui-navigators` and `ui-components` in that order, then starts the
  reader on port 5173.
- The reader fetches `https://reference-course.netlify.app/tutors.json` and renders it. It never reads a
  Markdown file.

## If you see 404 Page Not Found

The reader could not reach `reference-course.netlify.app`. Offline, a firewall and a mistyped course id all
look the same to it. CONTRIBUTING.md, "If the course does not load", shows how to serve a course from your own
machine instead. You will do exactly that in step 5.

## Explore

Open your browser's developer tools on the Network tab and reload. Find the one request for `tutors.json`.
Open its response and find the first topic. Keep this tab: the next lab follows that request through the code.

Leave `pnpm dev` running in its own terminal.
