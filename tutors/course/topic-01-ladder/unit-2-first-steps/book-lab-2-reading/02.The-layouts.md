# Layouts wrap the page

Before `+page.svelte` renders, layout files run, outermost first. The walkthrough lists three:

| File | What it does |
| --- | --- |
| `apps/reader/src/routes/+layout.server.ts` | reads the auth session and the locale and passes them down |
| `apps/reader/src/routes/+layout.svelte` | imports `app.css`, restores the saved theme, sets `<html lang>` |
| `apps/reader/src/routes/(course-reader)/+layout.svelte` | wraps every course route in `TutorsShell` from `@tutors/ui-navigators`, starts time tracking, loads the user's role, moves focus after navigation |

## Something does not match

Open `apps/reader/src/routes/`. At the pinned commit there is no `+layout.server.ts`. There is a
`+layout.ts`, and its opening comment explains why: every reader page now renders in the browser, and

> The root load is universal, not a server load (Rule 0771): it runs in the browser, so no navigation asks
> for __data.json and the static build (SVELTEKIT_ADAPTER=static) needs no server.

So the guide has drifted from the code. That is normal in a fast-moving repository, and it is exactly the
kind of thing a new contributor notices first. Write it down: it may become your first contribution at the
Summit. Before you open anything, check the repository's issues and pull requests in case someone has already
fixed it.
