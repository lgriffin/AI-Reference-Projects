# Conventional commits

This repository's own history does not use Conventional Commits, so you release from a scratch copy with a
history of its own. The image build needs the fixture beside the variant, so copy both:

~~~bash
export REL=/tmp/ladder-release
rm -rf $REL && mkdir -p $REL
cp -r $LADDER/variants/rung-7-shipped $LADDER/variants/fixtures $REL/
rm -rf $REL/rung-7-shipped/node_modules $REL/rung-7-shipped/out
cd $REL
git init -q -b main
git add -A
git commit -qm "chore: start from rung 7 (Shipped)"
git tag v1.0.0
cd rung-7-shipped && pnpm install --frozen-lockfile
~~~

`v1.0.0` is the release you are improving on. `CHANGELOG.md` already has its section.

## A fix

Open `apps/cli/src/run.ts`. The usage line names a file, not the command. Change both lines of the usage
message so they say `tutors-ladder <courseFolder> <outDir>` and `tutors-ladder --version`. Then:

~~~bash
pnpm test
git commit -qam "fix(cli): name the command tutors-ladder in its usage line"
~~~

## A feature

Add `--help` to `run`, just after `const [courseArg, outArg] = args;`:

~~~ts
  if (courseArg === "--help") {
    process.stdout.write("usage: tutors-ladder <courseFolder> <outDir>\n       tutors-ladder --version\n");
    return 0;
  }
~~~

~~~bash
node apps/cli/src/main.ts --help
pnpm test
git commit -qam "feat(cli): print the usage with --help"
~~~

## A commit that is not Conventional

~~~bash
git commit -q --allow-empty -m "Update stuff"
git log --oneline
~~~

Read the three messages. `type(scope): description` is the whole format; `!` after the scope, or a
`BREAKING CHANGE:` footer, marks a breaking change. Upstream reads the same types from pull request titles
(`scripts/release-changelog.ts`).
