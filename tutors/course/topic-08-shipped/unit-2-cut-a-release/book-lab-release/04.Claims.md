# Check the claims

~~~bash
pnpm release:claims
~~~

~~~
release/claims.yaml: 9 claims, each with evidence that exists and runs.
~~~

Pick one claim in `release/claims.yaml` and open its evidence. Would the test fail if the promise broke?

## Break one: a renamed test

Rename the evidence of `no-script` to a test that does not exist:

~~~bash
sed -i.bak 's/#the site has no script: no <script> element and no inline event handler/#the site has no scripts/' release/claims.yaml
pnpm release:claims; echo "exit $?"
~~~

~~~
release/claims.yaml: 1 problem(s). A release may not promise what no test checks.

- Claim "no-script" cites the test "the site has no scripts" in apps/cli/tests/release.test.ts, and no test there has that name. A test id is the exact name in test("..."). Did you mean: "the site has no script: no <script> element and no inline event handler", ...?
exit 1
~~~

The message names the rule, the offender and the fix: L4. Restore the file:

~~~bash
mv release/claims.yaml.bak release/claims.yaml
~~~

## Break one: a promise with no evidence

Add this claim at the end of `release/claims.yaml` and run the check again:

~~~yaml
  - id: fast-pages
    promise: Every page loads in under a second on a slow phone.
    evidence: []
~~~

Read the message. Then decide: can you write a test for that promise with what rung 7 has? If not, the
promise belongs in the changelog's prose, not in the claims. Remove it.

## Skip the evidence

In `apps/cli/tests/release.test.ts`, change `test("the site has no script: ...` to `test.skip(` and run
`pnpm release:claims`. Why does the check refuse a skipped test, when the gate would still be green?
Undo the change.
