# The readiness A3

~~~bash
pnpm release:readiness
~~~

~~~
**READY.** Nothing stands between this commit and a tag.
wrote /tmp/ladder-release/rung-7-shipped/out/readiness.md
~~~

Open `out/readiness.md` and read it top to bottom. It should take two minutes.

| Section | What it holds |
| --- | --- |
| 1. Background | the value in this release: your curated changelog section |
| 2. Current condition | each check, its standard, where it stands now, and the command that measured it |
| 3. Goal | what "ready" means, in one sentence |
| 4. Root cause analysis | each gap, and the prompt to ask why until the answer is a process or a tool |
| 5. Countermeasures | one per gap |
| 6. Plan | the SOP's steps, ticked when done; the last is always a person's |
| 7. Follow-up | what to compare next release |

If you skipped the container step, the verdict reads `READY, with one check not run`: a check that did
not run is not a pass. If you ran the smoke check before your last commit, it reads "not run" too: a pass
for another commit says nothing about this one.

## Make it hold

Edit any file and run it again without committing:

~~~bash
echo "" >> README.md
pnpm release:readiness
~~~

~~~
**HOLD.** 1 gap(s) stand between this commit and a tag; each is under Root cause.
~~~

A release is a commit, not a folder. Undo the edit (`git checkout README.md`).

## Tag it

This is step 8, and it is yours. In the scratch repository only:

~~~bash
pnpm test
git tag v1.1.0
git log --oneline --decorate -4
~~~

Nothing in rung 7 can run this for you: the fence fails any script that runs `git tag` or `git push`.
Upstream's `release-dispatch.yml` tags only candidates; the final `vX.Y.Z` is tagged by hand, after a
check that its tree is the last candidate's.
