# Exercises

1. **A breaking change.** In the scratch repository, change one line of `README.md` and commit it as
   `feat(cli)!: write the site to html/ by default` (the script reads only commits that touch the folder,
   so an empty commit will not do). Run `pnpm release:version --from v1.1.0`. Which version
   do you get, and where does the entry appear in the changelog section? What would it be for a workspace
   at 0.4.2?
2. **A security fix.** Commit `fix(security): ...` and find which Keep a Changelog heading it lands under.
   Read `SECTIONS` in `scripts/lib/conventional.ts`. Where would you put `revert:` commits, and why?
3. **Activate the CI.** In a fork of `AI-Reference-Projects`, copy `ladder-ci.yml` to `.github/workflows/`
   and open a pull request that touches the variant. Which jobs run? Mark `Ladder CI success` as required
   in branch protection and make one job fail on purpose.
4. **Refresh a digest.** Run `docker buildx imagetools inspect docker.io/library/busybox:1.37.0`. Does its
   digest still match the `Dockerfile`? If not, what changed, and what would the pull request that moves the
   pin need to say?
5. **A promise you cannot yet test.** Write down a promise you would like rung 7 to make that no test can
   check today (for example, "pages load fast on a slow phone"). What would it take to make it a claim?
   Which rung, or which upstream tool, has that capability?
6. **Upstream's changelog hints.** Read the "Writing an entry" note at the top of `$MONO/CHANGELOG.md`.
   Write the hints `(dom)` or `(headers)` that your two commits would carry if rung 7 had a harness.
