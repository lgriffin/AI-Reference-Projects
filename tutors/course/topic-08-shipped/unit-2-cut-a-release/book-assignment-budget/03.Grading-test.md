# The grading test

The grading test is in the variant: `variants/rung-7-shipped/tests/assignment/shipped.test.ts`. It is
skipped unless you ask for it, so the gate stays green before you start.

~~~bash
cd $LADDER/variants/rung-7-shipped
LADDER_ASSIGNMENT=1 node --test tests/assignment/*.test.ts
~~~

Before you start, all four tests fail:

~~~
not ok 1 - AC1: largest-page-bytes measures the largest HTML page, not the largest file
not ok 2 - AC2: a page over budget fails with a message that names the page and teaches
not ok 3 - AC3: release/slo.yaml has a largest-page objective, and the real site is within it
not ok 4 - AC4: release/claims.yaml promises it, with evidence that exists and runs
# pass 0
# fail 4
~~~

When you are done: `# pass 4`, and `pnpm test` still reports `# fail 0`.

## What it checks

| Test | How |
| --- | --- |
| AC1 | `MEASURES["largest-page-bytes"]` exists, its unit is `bytes`, and on a measurement where `tutors.json` is 9000 bytes and the largest page 5200, it reads 5200 |
| AC2 | `evaluate` with a 4096-byte budget fails, and the message contains `SLO "largest-page" exceeded`, the page's path and "Never raise a budget to make a release pass" |
| AC3 | `release/slo.yaml` is valid, has your objective with a budget of 16384 or less, and a real build of the fixture is within it |
| AC4 | the claim `pages-within-budget` passes the Closure Check, and its evidence file mentions `largest-page-bytes` |

Do not change the expectations to make the test pass: change the code.
