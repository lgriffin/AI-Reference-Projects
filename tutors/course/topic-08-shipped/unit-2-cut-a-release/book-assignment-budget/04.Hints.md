# Hints

One at a time. Try for ten minutes before you take the next.

## Hint 1: copy the neighbour

`site-bytes` is the shape to follow: a `unit`, a `what` (the words the message uses), a `read` from the
`Measurement` to a number, and an `advice`. Yours differs in which files it reads.

## Hint 2: only pages

`m.files` holds every file with its `path` and `bytes`. Filter on `path.endsWith(".html")`, then take the
largest. `Math.max(0, ...sizes)` gives 0, not `-Infinity`, for a site with no pages.

## Hint 3: the advice

`largest(m)` already formats the three largest files of a measurement. Call it with a measurement whose
`files` are only the pages: `largest({ ...m, files: pages })`. The message then names the page AC2 looks for.

## Hint 4: choosing the budget

Run `pnpm release:slo` after adding the objective with a generous budget, read the value, and set the
budget with headroom you can defend in one sentence in `why`. A budget so loose it never fails checks
nothing; one so tight it fails on the next typo fix teaches people to raise it.

## Hint 5: the claim's evidence

A test id is `<file>#<test name>`, with the exact name you gave `test("...")`. Run `pnpm release:claims`
before the grading test: if the id is wrong, its message says which names that file defines.

## Hint 6: the unknown-measure test

`scripts/tests/slo.test.ts` already has a test that lists the known measures in its expected message.
It is written so that adding a measure does not break it. Read it: why does it match `[^\]]*site-bytes[^\]]*`
rather than the exact list?
