# Objectives

Start from rung 6's standard version and cut a release. **Specify first**: write a release requirement
and a scenario, see it fail, and make the command say which release it is. Climb to rung 7 and read its
Rung Delta. Make two Conventional Commits and derive version 1.1.0 and its changelog from them. Break a
claim and a budget on purpose and read what each failure teaches. Build and smoke the image, or see why
the check skipped. Measure the release as a value stream, add the waits a machine cannot see, and find the
largest waste. Read the readiness A3 and tag the release yourself. Find the same ideas upstream, compare
your work with rung 7's standard version, build beyond, and end with a Kaizen step. Rung 7's assignment
follows the lab.

## Learning outcomes

| Outcome | Level | Module | Steps |
| --- | --- | --- | --- |
| Derive a version and a changelog from Conventional Commits; specify a release rule first and see it fail | Apply, Create | M6, M2 | 2, 4 |
| Trace a promise to its evidence, and diagnose which promise lost its proof | Analyse | M7, M4 | 3, 5, 6, 9 |
| Judge whether a commit is ready to release, from evidence on an A3 | Evaluate | M7 | 5, 6, 8, 10 |
| Map the release value stream with measured times, and find its largest waste | Analyse, Evaluate | M8 | 7, 12 |
| Extend the release without weakening a rule, and improve the standard work | Create, Evaluate | M8, M2 | 11, 12 |

Each step's heading names its Bloom level.

You need Node.js 22.18 or later, pnpm 10, Git, a Chromium-based browser, and the `LADDER` and `MONO`
variables from Lab 1 (`LADDER` is `AI-Reference-Projects/tutors`, `MONO` your clone of tutors-mono-repo).
Docker is optional: step 6 says what you see without it. Allow about three hours. Commit after each step
that changes code, so that every break can be undone with `git checkout .`.
