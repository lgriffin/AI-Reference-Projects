## What this week adds

Rung 7 is a copy of rung 6 with nothing taken away. It adds eight requirements, R-037 to R-044, and the
code that keeps them:

- **a name**: one SemVer version derived from Conventional Commits, a curated changelog, and a build
  identity in `--version` and `version.json`;
- **promises**: `release/claims.yaml`, each claim tied to requirements and to tests, closed by
  `pnpm release:claims`;
- **budgets**: `release/slo.yaml`, checked by `pnpm release:slo`;
- **a thing that runs**: a `Dockerfile` pinned by digest, a smoke check, and a CI template;
- **a view**: the release value stream (`pnpm release:value-stream`) and the readiness A3
  (`pnpm release:readiness`).

It adds one dev dependency, `yaml`, for the release scripts and the tests. This is rung 7's only week, so
it ends with the assignment (A7), the exit criteria on the topic page, and a comparison with rung 7's
standard version.

## The value it delivers

Rung 7 has three customers. The **lecturer** who installs a release knows what changed and what they may
rely on. The **maintainer** looking at a bug report can ask any site which commit built it. The
**contributor** gets a release that cannot promise what no test checks, with failures that say what to do.
In the value stream from week 1, rung 7 is the last hand-over: from the team to everyone else.
