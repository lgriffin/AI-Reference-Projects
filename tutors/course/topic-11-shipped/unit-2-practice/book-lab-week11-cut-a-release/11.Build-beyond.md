# Build beyond (Create)

Take rung 7 further than it goes. Each extension starts from a value to someone, begins with Specify first
(`pnpm test:ears:audit --next-id`, a sentence that says what the release reports or decides, a Rule with a
scenario, seen red), and stays inside the Rung Fence: no new dependency, no release tool, no script that
tags, pushes or publishes. Removing a claim, raising a budget, lowering a mutation floor, or changing a
digest or an action SHA is on the "Ask a human first" list: ask your lecturer or a neighbour, and record
their answer in the commit. Write every commit as a Conventional Commit, and release your extension as
1.2.0 by the SOP.

## 1. A release line in the map

Value: the Reviewer sees whether releases are getting slower. `pnpm release:value-stream` writes
`out/value-stream.json` and overwrites it each time. Keep a history instead: append one line per run to an
append-only file, as the harness's scoreboard does, and show the last three lead times in the A3's
Follow-up section. The arithmetic belongs in `scripts/lib` as a pure function with unit tests, so that
Stryker sees it. What should the A3 say when there is only one run?

## 2. A security section that cannot be forgotten

Value: a lecturer learns that a release fixes a vulnerability without reading every line. `fix(security)`
commits already land under "Security". Add a claim: a release whose commits include a security fix has a
"Security" section in its changelog. What is the evidence, and can it be a test in the gate, or only a
check at release time? Write the requirement first and decide which.

## 3. The reader in the image

Value: the image a host runs is the product a learner uses. Rung 7's image serves the static site only
(`RUNG.md`, "Deliberately left out"). Add a build stage that installs from the lockfile and builds the
reader, and serve it beside the site. Extend the smoke check with one fact about the reader, and its pure
half in `scripts/lib/smoke.ts` with a unit test. Measure before and after with `pnpm release:value-stream`:
what did the step cost in process time, and in image size? Is the value worth it?

## 4. Activate the CI

Value: the gate runs for every contributor, not only for those who remember. In a fork of
AI-Reference-Projects, copy `ladder-ci.yml` to `.github/workflows/` and open a pull request that touches
the variant. Which jobs run? Mark `Ladder CI success` as required in branch protection and make one job
fail on purpose. Then add the waits you observe (queue time for a runner) to your value stream map with
`--wait`. Changing the workflow's `permissions` needs a person's yes.

For each extension you build, add a line to `RUNG.md`'s upstream mirror table if it mirrors something
upstream, add or extend a claim if it is a promise, and run every gate: `pnpm test`,
`pnpm test:ears:audit`, `pnpm test:e2e`, `pnpm audit:supply-chain`, `pnpm release:claims`,
`pnpm release:slo`, then `pnpm test:mutation` and `pnpm check:mutation-floors` if you changed `packages/`
or `scripts/lib`.
