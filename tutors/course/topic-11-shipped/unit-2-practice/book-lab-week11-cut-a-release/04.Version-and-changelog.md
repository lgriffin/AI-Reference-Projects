      When the command is asked for "--help"

And its steps to `command.steps.ts`, before the Rule for `--json-only`:

~~~ts
  Rule("When the command is given --help alone, the command shall print its usage and exit with status 0.", ({ RuleScenario }) => {
    RuleScenario("--help on its own", ({ When, Then, And }) => {
      When("the command is asked for {string}", async (_ctx, flag: string) => {
        const stdout = vi.spyOn(process.stdout, "write").mockImplementation(() => true);
        try {
          status = await run([flag]);
          printed = stdout.mock.calls.map(([chunk]) => String(chunk)).join("");
        } finally {
          stdout.mockRestore();
        }
      });
      Then("it exits with status {int}", (_ctx, expected: number) => {
        expect(status).toBe(expected);
      });
      And("it printed its usage on standard output", () => {
        expect(printed).toContain("usage: node apps/cli/src/main.ts");
      });
    });
  });
~~~

## A commit that is not Conventional

~~~bash
echo "" >> README.md
git commit -qam "Update notes"
git log --oneline
~~~

~~~
aa1f783 Update notes
f6b0309 feat(cli): print the usage with --help
7b1f2ae docs(requirements): R-045, --help prints the usage
ae3d15e fix(cli): name the option the command does not know
3bcb51d chore: rung 7, as shipped
~~~

Your hashes differ. `type(scope): description` is the whole format. `!` after the scope, or a
`BREAKING CHANGE:` footer, marks a breaking change.
