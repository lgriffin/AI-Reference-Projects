## The problem

A lecturer reports that a page looks wrong. You ask which version they built it with. They do not know,
and neither does the site: nothing rung 6 writes says which release made it. Try:

~~~bash
node apps/cli/src/main.ts --version; echo "exit $?"
~~~

~~~
usage: node apps/cli/src/main.ts [--json-only] [--private] <courseFolder> <outDir>
exit 2
~~~

Who is the customer of a version number? What does it cost them when it is missing?

## 1. The requirement

~~~bash
pnpm test:ears:audit --next-id
~~~

~~~
R-037
~~~

A release requirement is written like any other, with one habit: it says what the software **reports and
decides**, never what a person does. "The maintainer shall tag the release" is not a requirement of this
code. Write yours for `--version` before you read on. Then compare it with this one, and add a row to the
table in `REQUIREMENTS.md`, after R-036:

~~~markdown
| R-037 | Event-driven | When the command is given --version alone, the command shall print the release version and write no file. | cli |
~~~

One trigger, one system, one "shall", and something a test can observe. Why "and write no file"?

## 2. The scenario

Create `tests/bdd/features/command/version.feature`:

~~~gherkin
@release
Feature: A build says which release it is
  As a maintainer reading a bug report
  I want to ask the command which release it is
  So that I know which source made the site a learner saw

  @R-037 @ears-event-driven
  Rule: When the command is given --version alone, the command shall print the release version and write no file.

    Scenario: --version on its own
      When the command is run with "--version" in an empty folder
      Then it exits with status 0
      And it printed the version in apps/cli/package.json
      And the folder is still empty
~~~

And its steps, `tests/bdd/steps/command/version.steps.ts`:

~~~ts
import { mkdtempSync, readdirSync, readFileSync } from "node:fs";
import { tmpdir } from "node:os";
import { join } from "node:path";
import { describeFeature, loadFeature } from "@amiceli/vitest-cucumber";
import { expect, vi } from "vitest";
import { run } from "../../../../apps/cli/src/run.ts";
import { ROOT } from "../../../support/paths.ts";

const feature = await loadFeature("tests/bdd/features/command/version.feature");

describeFeature(feature, ({ Rule }) => {
  let folder: string;
  let status: number;
  let printed: string;

  Rule("When the command is given --version alone, the command shall print the release version and write no file.", ({ RuleScenario }) => {
    RuleScenario("--version on its own", ({ When, Then, And }) => {
      When("the command is run with {string} in an empty folder", async (_ctx, flag: string) => {
        folder = mkdtempSync(join(tmpdir(), "lab-11-version-"));
        const stdout = vi.spyOn(process.stdout, "write").mockImplementation(() => true);
        const stderr = vi.spyOn(process.stderr, "write").mockImplementation(() => true);
        try {
          status = await run([flag]);
          printed = stdout.mock.calls.map(([chunk]) => String(chunk)).join("");
        } finally {
          stdout.mockRestore();
          stderr.mockRestore();
        }
      });
      Then("it exits with status {int}", (_ctx, expected: number) => {
        expect(status).toBe(expected);
      });
      And("it printed the version in apps/cli/package.json", () => {
        const { version } = JSON.parse(readFileSync(join(ROOT, "apps", "cli", "package.json"), "utf8"));
        expect(printed).toBe(`tutors-ladder ${version}\n`);
      });
      And("the folder is still empty", () => {
        expect(readdirSync(folder)).toEqual([]);
      });
    });
  });
});
~~~

The scenario does not say `1.0.0`. It says "the version in apps/cli/package.json", so it stays true after
the next release.

## 4. Make it green

In `apps/cli/src/run.ts`, add `readFile` to the import from `node:fs/promises`, and put this at the top of
`run`, before `const flags`:

~~~ts
  if (args.length === 1 && args[0] === "--version") {
    const { version } = JSON.parse(await readFile(new URL("../package.json", import.meta.url), "utf8")) as { version: string };
    process.stdout.write(`tutors-ladder ${version}\n`);
    return 0;
  }
~~~
