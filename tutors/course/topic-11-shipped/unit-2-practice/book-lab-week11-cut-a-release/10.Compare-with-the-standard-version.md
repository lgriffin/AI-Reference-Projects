Rung 7's completed code ships as a zip, the **standard version**, in this week's practice unit, "Rung 7
(shipped): the standard version". It is the last standard version on the ladder: next week you work in
tutors-mono-repo itself. Do this step after the assignment.

~~~bash
mkdir -p ~/ladder/standard7 && cd ~/ladder/standard7
unzip -q ~/Downloads/rung-7-shipped.zip
ls tutors-ladder
cd tutors-ladder/rung-7-shipped
~~~

## Compare your rung 7

~~~bash
diff -rq --exclude=node_modules --exclude=.git --exclude=build --exclude=.svelte-kit --exclude=static --exclude=reports --exclude=out \
  ~/ladder/standard7/tutors-ladder/rung-7-shipped ~/ladder/rung7/tutors-ladder/rung-7-shipped
~~~

After the lab and the assignment you should see `REQUIREMENTS.md`, `CHANGELOG.md`, the three
`package.json` files (yours say 1.1.0 or later), `apps/cli/src/run.ts`, the command feature and its steps,
`scripts/lib/slo.ts`, `release/slo.yaml`, `release/claims.yaml`, your own tests, and perhaps
`tests/mutation/mutation-floors.json` if you raised a floor.

For each difference, write one line: the lab, the assignment, a Build beyond extension, a Kaizen
improvement, or drift you did not mean. Put the drift back. Check four files with special care. This
prints what changed in them since your first commit:

~~~bash
cd ~/ladder/rung7/tutors-ladder/rung-7-shipped
git diff --stat v1.0.0 -- tests/rung-fence.test.ts tests/architecture Dockerfile .github
~~~

It should print nothing. Then check that no budget was raised and no claim removed:

~~~bash
git diff v1.0.0 -- release/slo.yaml release/claims.yaml | grep "^-[^-]"
~~~

Every line it prints is something the standard version had and yours does not. A removed claim or a raised
budget needs a person's decision: say who decided, and where that is recorded.
