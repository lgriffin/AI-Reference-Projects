# Hints

One at a time. Try for ten minutes before you take the next.

## Hint 1: the sentence

It is an unwanted-behaviour requirement: "If *what went wrong*, then the release shall *report what* and
*decide what*." R-041 is its neighbour; read it, and make yours say something R-041 does not: which page.
The system is "the release". `scripts/checks/ears-audit.ts` knows that system since this rung.

## Hint 2: the scenario

R-041's scenarios in `release.feature` are the shape to follow: an objective, a build, "the release judges
the build", an exit status, what it reported. Your Given needs a build with a named page of a given size.
vitest-cucumber does not let one scenario register the same step text twice, so give your steps their own
wording.

## Hint 3: copy the neighbour

`site-bytes` in `MEASURES` is the shape to follow: a `unit`, a `what` (the words the message uses), a
`read` from the `Measurement` to a number, and an `advice`. Yours differs in which files it reads.

## Hint 4: only pages

`m.files` holds every file with its `path` and `bytes`. Filter on `path.endsWith(".html")`, then take the
largest. `Math.max(0, ...sizes)` gives 0, not `-Infinity`, for a site with no pages.

## Hint 5: the advice

`largest(files)` already formats the three largest files of a list. Call it with the pages only. The
message then names the page AC3 looks for.

## Hint 6: choosing the budget

Add the objective with a generous budget, run `pnpm release:slo`, read the value, and set the budget with
headroom you can defend in one sentence in `why`. A budget so loose it never fails checks nothing. One so
tight it fails on the next typo fix teaches people to raise it.

## Hint 7: the claim's evidence

A test id is `<file>#<test name>`, with the exact name you gave `test("...")`. Run `pnpm release:claims`
before the grading test: if the id is wrong, its message suggests the names that file defines. And
`tests/release/budgets.test.ts` holds a Budget rule: a measure with no objective fails the gate. Add the
objective in the same commit as the measure.

## Hint 8: the floor

`scripts/lib/slo.ts` is mutated by Stryker and has a floor of 98. If `pnpm check:mutation-floors` says it
slipped after `pnpm test:mutation`, a mutant in your measure survived: your own test does not notice some
change. Open `reports/mutation/index.html`, find it, and add the row that kills it. Do not lower the floor.
