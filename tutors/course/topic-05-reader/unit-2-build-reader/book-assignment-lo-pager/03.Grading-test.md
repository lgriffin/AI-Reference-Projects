# The grading test

The grading tests are already in the variant, skipped until you ask for them:

| File | Checks |
| --- | --- |
| `tests/assignment/lo-pager.grading.test.ts` | AC4, AC2, AC3 on upstream's `tutors.json` for the fixture; AC5's files; AC1's `<LoPager>` in `Note.svelte` and `Lab.svelte` |
| `tests/assignment/lo-pager.e2e.ts` | AC1 to AC3 in Chromium: from the first talk, through the note, to the lab |

Run them with:

~~~bash
cd tutors/variants/rung-4-reader
pnpm test:assignment
~~~

That sets `ASSIGNMENT=1`, runs the unit grading tests, builds the reader and runs the browser check.
Before you start, every grading test fails with a message naming the criterion:

~~~
not ok 1 - AC4: the reading order is the course's talks, notes and labs, in pre-order
  error: "AC5: put the pager's logic in apps/reader/src/lib/course/lo-pager.ts, plain TypeScript, so node --test can run it."
~~~

When you are done, `pnpm test:assignment` shows `# fail 0` twice, and `pnpm test` still shows the three
grading tests as skipped and everything else passing.

## How the grading test reads your code

The unit test imports your module by a computed path, so the gate compiles before the file exists:

~~~ts
const pager = (await import(file)) as Pager;
const { decorateCourseTree } = await import(join(READER, "src", "lib", "course", "lo-tree.ts"));
return { pager, tree: decorateCourseTree(JSON.parse(readFileSync(ORACLE, "utf8")), "sample") };
~~~

`ORACLE` is `variants/fixtures/ladder-sample-course.tutors.json`, written by upstream's generator. Your
pager is graded against the contract, not against your own generator.

The browser check finds the pager by its accessible name, so the label matters:

~~~ts
const pager = page.getByRole("navigation", { name: "Learning object pager" });
~~~
