# The brief

## What a learner sees

On every talk, note and lab page, below the content, a navigation bar labelled **Learning object pager**
with up to two links:

- `← <title>` to the previous learning object in reading order, unless this is the first;
- `<title> →` to the next one, unless this is the last.

Reading order is the order the course holds its talks, notes and labs in `tutors.json`: topic by topic, unit
by unit, side units after units. Courses, topics, units, sides, web links and archives are not stops. For the
sample course the order is **Welcome**, **Reading Guide**, **Lab-01-First-Steps**.

## Where it goes

| Part | File |
| --- | --- |
| the logic | `apps/reader/src/lib/course/lo-pager.ts`, exporting `readingOrder(tree)` and `loNeighbours(tree, lo)` |
| its unit tests | `apps/reader/tests/lo-pager.test.ts`, yours to write |
| the component | `apps/reader/src/lib/ui-navigators/LoPager.svelte` |
| where it shows | `content/Note.svelte` (talks and notes) and `content/lab/Lab.svelte` |

```ts
export function readingOrder(tree: CourseTree): PageLo[];
export function loNeighbours(tree: CourseTree, lo: Lo): { previous?: PageLo; next?: PageLo };
```

## What not to do

- Do not add a dependency or change `tests/rung-fence.test.ts`, `tests/architecture/` or the grading test.
- Do not put the logic in the component: `lib/course` is plain TypeScript so `node --test` can check it.
- Do not change the lab's own step pager. The two pagers sit side by side and have different labels.
