# A lab step

Open <http://localhost:5173/lab/ladder-sample-course/topic-02-practice/unit-1-lab/book-1-first-lab/Setup>.

| File | What happens |
| --- | --- |
| `routes/(course-reader)/lab/[courseid]/[...loid]/+page.ts` | calls `readLab` with the whole path |
| `lib/course/course-service.ts`, `readLab` | the path is not a lab, so it cuts the last segment (`Setup`) and looks up the rest |
| `lib/course/live-lab.ts`, `liveLab(lab, "Setup")` | the step, its index and its neighbours, as plain data |
| `lib/ui-components/content/lab/Lab.svelte` | the step list with `aria-current="step"`, the step's Markdown, the pager |
| `lib/ui-primitives/Markdown.svelte` | `renderMarkdown` from `@ladder/lite`, the one `{@html}` |

Now press the right arrow. `navigateStep` in `Lab.svelte` calls `goto(next.route)`; the load runs again;
`$derived(liveLab)` recomputes the step.

## A step that is not there

Change `Setup` in the address bar to `Nope`. You get a 404 page with `Not found: a lab step at ...`.
Find where that message is made (`routes/(course-reader)/found.ts`) and why the course service returns
`undefined` instead of throwing (`lib/course` may not use SvelteKit: the Framework rule).

## Run the logic without a browser

~~~bash
node --test apps/reader/tests/live-lab.test.ts apps/reader/tests/course-service.test.ts
~~~

The course service test passes its own `fetch`, counts requests and proves the course is fetched once.
