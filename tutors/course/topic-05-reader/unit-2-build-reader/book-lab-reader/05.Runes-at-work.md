## Take away a `$derived`

In `apps/reader/src/lib/ui-components/structure/Composite.svelte`, change

~~~svelte
const { units, sides, standardLos } = $derived(arrange(composite));
~~~

to

~~~svelte
const { units, sides, standardLos } = arrange(composite);
~~~

Run `pnpm typecheck`. `svelte-check` reports:

~~~
WARNING "src/lib/ui-components/structure/Composite.svelte" ... "This reference only captures the initial
value of `composite`. Did you mean to reference it inside a closure instead?
https://svelte.dev/e/state_referenced_locally"
~~~

and the gate fails, because the reader runs `svelte-check --fail-on-warnings`. Without `$derived`, a
`Composite` reused for a new topic would keep the old topic's cards. Put `$derived` back.

Upstream turns this warning off for every app (`onwarn` in `packages/svelte/app-config/src/svelte.js`). Why
might a large codebase choose that, and what does it cost?
