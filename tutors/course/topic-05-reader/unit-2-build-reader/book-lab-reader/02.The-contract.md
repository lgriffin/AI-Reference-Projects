# The contract

`pnpm dev` and `pnpm build` both start with `pnpm course`:

~~~bash
pnpm course
~~~

~~~
wrote 0 pages and tutors.json to .../apps/reader/static/courses/ladder-sample-course
~~~

That is the cli from rung 3 with `--json-only` (`apps/cli/src/run.ts`). The reader is served from
`apps/reader/static`, so this file becomes `/courses/ladder-sample-course/tutors.json`.

## Look inside

~~~bash
node -e '
const c = require("./apps/reader/static/courses/ladder-sample-course/tutors.json");
const walk = (lo, d) => { console.log("  ".repeat(d) + lo.type.padEnd(8) + lo.route); (lo.los ?? []).forEach((l) => walk(l, d + 1)); };
walk(c, 0);'
~~~

You should see routes such as `/topic/{{COURSEURL}}/topic-01-basics`. The placeholder is filled in by the
reader, not the generator, because only the reader knows which id the course was opened with.

## Compare with upstream's file

The fixture's upstream-generated `tutors.json` sits at `../fixtures/ladder-sample-course.tutors.json`.
Run the same walk on it. The routes match. Upstream's file has more fields (`img`, `frontMatter`,
`properties`, ...); the reader ignores what it does not use.

`apps/reader/tests/lo-tree.test.ts` reads **upstream's** file, not ours. So the reader is tested against
the contract as upstream writes it.
