# Assignment 6: raw HTML and locked content

Rung 6's coding assignment (A6 in `course.md`), assessed at the **Create** level of Bloom's taxonomy. It
assesses module outcomes M7 (evaluate the safety of a system from evidence: escaping and sanitising,
threats) and M6 (specify behaviour with EARS requirements and Given/When/Then scenarios).

Two small security features for rung 6, each mirroring something real in tutors-mono-repo:

- **Part A, content safety:** a rule in the generator that warns when a course's Markdown holds raw HTML,
  such as an `<iframe>` or a `<script>`, outside code. Rung 6 shows raw HTML as escaped text; upstream's
  reader sanitises it away. Either way the author is surprised, so tell them at build time, as upstream's
  rule V016 does for slides.
- **Part B, authorisation:** content locks. Upstream educators can lock a topic or unit so that students
  do not see it (`guides/RBAC.md`, "Content Locking"). Add the pure policy for it to `@ladder/rbac`.

Both are specified first, the way this week taught: an EARS requirement and a Rule with a scenario, seen
red, before any code. The code is about fifty lines. The sentences, the look-alikes and the purity are the
work.

You may work with a coding agent. The Rung Fence and the architecture rules still hold, the requirements
are yours to write and have approved by a person, and every line is yours to explain.
