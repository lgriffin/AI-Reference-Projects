# Hints

Try each hint only when the one before it is not enough.

## The sentences

1. Part A is something that happens when a page is read: event-driven, "When ..., the generator shall
   ...", or unwanted behaviour, "If ..., then the generator shall ...". Which is raw HTML: an event or an
   attack? Either can pass; be ready to defend your choice.
2. The response must be observable. "shall handle raw HTML safely" fails the audit's vague-language check
   and tells a tester nothing. "shall warn, naming the file and the element" can be seen.
3. Part B's system is "the policy" (`packages/rbac`), and its layer is `rbac`. Look at R-030 and R-031.

## Part A

1. Start from `prose()` in `packages/gen/src/portable.ts`: it already removes fenced and inline code.
2. A raw tag starts `<`, then a letter, then letters or digits, then a space, `/` or `>`. A lookahead,
   `(?=[\s/>])`, keeps `<hello@tutors.dev>` out.
3. `Array<string>` still matches hint 2. Keep a `Set` of HTML element names (`iframe`, `script`, `object`,
   `embed`, `form`, `input`, `svg`, `img`, `style`, `a`, `meta`, `b`, `div`, `span`, ...) and report only
   those. That is an allow-list of what counts as HTML. Upstream's V016 takes the other road: it looks only
   for what the sanitiser strips (`STRIPPED` in `packages/jsr/course-rules/src/rich.ts`). Which is better
   for authors, and why is a block-list acceptable in a warning?
4. Call it beside `warnOutside` in `packages/gen/src/course-builder.ts`, but for every kind of page, not
   only those outside `STAYS`.

## Part B

1. Read upstream's `isLoRouteLocked` and `normalizeRoute` in
   `packages/svelte/utils/rbac/src/rbac-service.svelte.ts`. Port the logic, not the runes.
2. Compare paths **after the type segment**: `/lab/cs101/week-01/lab-03` and `/topic/cs101/week-01` share
   `cs101/week-01`. A lock path needs at least two segments (a course id and one more).
3. `path.startsWith(lockPath)` matches `week-010` under `week-01`. Compare with `` `${lockPath}/` ``.
4. Trailing slashes: a loop from the end, not `/\/+$/`. Upstream's comment says why (CodeQL
   `js/polynomial-redos`). The Purity rule allows a `let` inside a function, not at the top of the module.

## The gate

1. `tests/contract/package-api.test.ts` lists each package's exports. A new export is a decision: add it
   to the list in the same commit as the function.
2. A surviving mutant in your new code is a hidden defect in security logic. Add a row, do not lower a
   floor.
