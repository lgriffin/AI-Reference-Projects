# The grading test

It is already in the variant: `tests/assignment/guarded.grading.test.ts`, labelled "Assignment 6". Read it
before you write any code; it is part of the specification. Three things to notice:

- **It is skipped by default.** Each `describe` is skipped unless `LADDER_ASSIGNMENT=1`, so the variant's
  gate stays green until you start (the gate's `32 skipped`). `pnpm test:assignment` sets the variable.
- **It imports your code dynamically.** `rawHtmlFindings` does not exist yet, so a static import would fail
  the whole file. The helpers `gen()` and `rbac()` import the package and fail with AC2, AC6 or AC8 if a
  function is missing.
- **It finds your requirements by their words, not their ids.** AC1 looks after R-036 for a sentence with
  "raw HTML" and "the generator shall", and one with "lock" and "the policy shall", then runs the whole
  closure audit.

## Grade it

~~~bash
pnpm test:assignment
~~~

Before you start:

~~~
 Test Files  1 failed (1)
      Tests  32 failed (32)
~~~

When you are done:

~~~
 Test Files  1 passed (1)
      Tests  32 passed (32)
~~~

Every failure names its criterion and the fix. For example:

~~~
AC1: add a requirement after R-036 (pnpm test:ears:audit --next-id) that says what the generator shall do when a page holds raw HTML.
AC3: rawHtmlFindings should return ["form","input"]: each HTML element's lower-case name once, in order of first appearance.
AC7: normalise with a loop, as upstream normalizeRoute does (CodeQL js/polynomial-redos).
~~~

## What it checks

| Test | Count | How |
| --- | --- | --- |
| AC1 | 1 | parses `REQUIREMENTS.md` with the audit's own `parseRequirements`, then runs the whole audit and expects no finding |
| AC2, AC3 | 12 | eleven raw-HTML inputs, and one with several tags, each reported once and in order |
| AC4 | 7 | comparisons, a code span, two fenced blocks, generics, arrows, an autolink: no finding |
| AC5 | 1 | builds a course in `MemoryFileSystem` and expects two warnings, for `course.md` `<b>` and `note.md` `<iframe>`, and none for a `<script>` in a code span |
| AC6 | 9 | upstream's lock-matching table |
| AC7 | 1 | a route ending in 200,000 slashes, answered in under half a second |
| AC8 | 1 | an educator, a student and an anonymous reader on a locked route |

Then run the Single Gate: `pnpm test`. The closure audit, the architecture tests (which keep your lock
policy pure) and the Rung Fence must stay green too.
