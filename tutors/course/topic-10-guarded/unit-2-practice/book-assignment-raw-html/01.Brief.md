# The brief

Work in your `tutors-ladder/rung-6-guarded` from Lab 10 (or a fresh copy of rung 6's standard version, with
`../fixtures` beside it). Commit after each numbered step.

~~~bash
cd ~/ladder/rung6/tutors-ladder/rung-6-guarded
git status                # clean: undo the lab's experiments with git checkout .
pnpm test:assignment      # 32 tests, all red: nothing is written yet
~~~

## Specify first

1. **Two sentences.** Take the next ids with `pnpm test:ears:audit --next-id` (R-037, then R-038). Write
   two requirements in `REQUIREMENTS.md`:
   - one that says what **the generator shall** do when a page holds **raw HTML** (Part A);
   - one that says what **the policy shall** answer for a **locked** route (Part B).

   Choose the EARS pattern for each. Show both sentences to a person (a peer, or your tutor) before you go
   on. Commit them on their own.
2. **Two Rules.** Add each sentence as a `Rule:`, word for word, with its id and EARS tag: the generator's
   in `tests/bdd/features/generator/containment.feature` (or a new feature beside it), the policy's in
   `tests/bdd/features/policy/access.feature`. Give each at least one adversarial scenario. Bind them. See
   them fail. Commit.

## Part A: raw HTML in Markdown

3. Add `packages/gen/src/raw-html.ts`, exporting `rawHtmlFindings(markdown: string): string[]` from
   `@ladder/gen`. It returns the lower-case names of the **HTML elements** written as raw tags in the
   Markdown, each once, in order of first appearance. Code is not raw HTML: leave out fenced blocks and
   inline code spans, as `packages/gen/src/portable.ts` already does. Text that only looks like a tag is not
   raw HTML either: `a < b`, `Array<string>`, `Map<K, V>`, `->`, and an autolink such as
   `<hello@tutors.dev>`.
4. Make `buildCourse` call it for every `.md` and `.marp` file it reads, in every folder (the course, units
   and sides too), and pass one warning per file and tag to `options.warn`:

   ~~~
   raw-html topic-1/note-1/note.md: <iframe> is raw HTML. ...
   ~~~

   The text after the tag is yours: say what rung 6 does with it, what the Summit's reader does with it,
   and what the author should do instead. A warning is a Teaching Failure for a course author.

## Part B: locked content

5. Add two functions to `packages/rbac/src/index.ts`:
   - `isLoRouteLocked(route: string, locks: ReadonlyMap<string, boolean>): boolean`, mirroring upstream's
     function of the same name in `packages/svelte/utils/rbac/src/rbac-service.svelte.ts`;
   - `canSeeLo(role: Role, route: string, locks: ReadonlyMap<string, boolean>): boolean`: educators see
     everything; everyone else sees what is not locked.

   `@ladder/rbac` must stay pure: the Purity rule in `tests/architecture/architecture.test.ts` still applies.

## Finish

6. Run every gate: `pnpm test`, `pnpm test:ears:audit`, `pnpm test:e2e`, `pnpm audit:supply-chain`. The
   `package-api` contract will tell you that two packages export something new: that is true, so update its
   lists on purpose, and say so in the commit message.
7. Run `pnpm test:mutation`, then `pnpm check:mutation-floors`. The grading test is not part of the
   mutation run, so your new code needs unit rows of its own: a table for `canSeeLo` in
   `tests/unit/rbac/policy.test.ts`, and rows for `rawHtmlFindings` in `tests/unit/gen/`. Never lower a
   floor.
8. Add your two features to `RUNG.md`'s upstream mirror table, with the upstream files they mirror.
