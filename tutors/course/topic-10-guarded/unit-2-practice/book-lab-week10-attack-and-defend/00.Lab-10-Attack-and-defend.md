# Objectives

Start from rung 5's standard version and treat the course author as an adversary. **Specify first**: write
a security requirement and an adversarial scenario, see it fail, then attack rung 5 for real and watch
script run. Write a small defence, find its hole, and climb to rung 6 to see the full one. Read a private
file through a link, then watch containment refuse it. Test the last wall, the Content Security Policy, in
a browser. Build a private course on purpose. Break a defence, read what the gate teaches, and ask why five
times. Find the same ideas upstream, compare your work with rung 6's standard version, build beyond, and end
with a Kaizen step. Rung 6's assignment follows the lab.

## Learning outcomes

| Outcome | Level | Module | Steps |
| --- | --- | --- | --- |
| Model the threats: place each attack on the trust boundary it crosses | Analyse | M7 | 1, 3, 5, 7 |
| Specify a security rule first, with an adversarial scenario, and see it fail | Apply, Create | M6, M2 | 2 |
| Tell escaping from sanitising and containment, and diagnose which wall an attack passed | Analyse | M7, M4 | 3, 4, 5, 6, 8 |
| Judge which defence and which Assertion Ladder level fits a risk, from evidence | Evaluate | M7 | 4, 6, 8, 9, 10 |
| Extend the variant without weakening a rule, and improve the standard work | Create, Evaluate | M2, M8 | 11, 12 |

Each step's heading names its Bloom level.

You need Node.js 22.18 or later, pnpm 10, Git, a Chromium-based browser, and the `LADDER` and `MONO`
variables from Lab 1 (`LADDER` is `AI-Reference-Projects/tutors`, `MONO` your clone of tutors-mono-repo).
Step 5 makes a symbolic link; on Windows use WSL. Allow about three hours. Commit after each step that
changes code, so that every break can be undone with `git checkout .`.
