# Build beyond (Create)

Take rung 6 further than it goes. Each extension starts from a value to someone, begins with Specify first
(`pnpm test:ears:audit --next-id`, a sentence, a Rule with an adversarial scenario, seen red), and stays
inside the Rung Fence: no new dependency, no new package, no weaker policy. Changing `CSP`, `safeUrl`'s
schemes or the policy's answers is on the "Ask a human first" list: ask your lecturer or a neighbour, and
record their answer in the commit.

## 1. A payload of your own

Value: the next author's attack is already known. Find a payload in the
[OWASP XSS Filter Evasion Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/XSS_Filter_Evasion_Cheat_Sheet.html)
that is not in `tests/unit/lite/xss-corpus.test.ts`. Add it to `HOSTILE_URLS` or `HOSTILE_TEXT` with its
reason. Does it pass? If it fails, you found a bug: fix `url.ts`, not the test.

## 2. A stricter image rule

Value: a student's reading is not reported to a third party by an image request. Rung 6 lets images load
from any `https:` host. Should a course image load only from the course's own site? Write the requirement
first. Change `img-src` in `CSP` and `ALLOWED.image` in `url.ts` together, and update the tests. What breaks
for a course that shows a diagram from a CDN? Who should decide?

## 3. A third adapter

Value: a lecturer can build a course from a zip a colleague sent, without unpacking it. Write a
`ZipFileSystem` that implements `FileSystemPort` over an in-memory map of a zip's entries (fake the zip as a
`Record<string, string>` with `../` names in it). Run the gate before you add it to the contract test: which
rule fails first? Then make it pass the containment cases.

## 4. A sign-in for the tests

Value: the reader's refusal for an enrolled and a not-enrolled reader is proved, not assumed. Rung 6's
reader only ever meets `AnonymousSession`. Add scenarios for R-032 that pass a `FakeSession` for `bob` (on
the whitelist) and `eve` (not on it) to `requestLo`, and check the two notices. No real sign-in: that is the
Summit's.

For each extension you build, add a line to `RUNG.md`'s upstream mirror table if it mirrors something
upstream, and run every gate: `pnpm test`, `pnpm test:ears:audit`, `pnpm test:e2e`, `pnpm audit:supply-chain`,
then `pnpm test:mutation` and `pnpm check:mutation-floors` if you changed `packages/`.
