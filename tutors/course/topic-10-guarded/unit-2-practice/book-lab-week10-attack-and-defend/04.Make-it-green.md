## The smallest allow-list

Implement R-022 in the layer its row names. In `packages/lite/src/markdown.ts`, add above `emphasis`:

~~~ts
/** The schemes a course link may use. An address with any other scheme is refused. */
const ALLOWED = new Set(["http", "https", "mailto"]);

/** True for an address with an allowed scheme, or with none (a relative address). */
function allowedLink(url: string): boolean {
  const scheme = url.match(/^([a-z][a-z0-9+.-]*):/i)?.[1];
  return scheme === undefined || ALLOWED.has(scheme.toLowerCase());
}
~~~

and in `renderInline` replace the `return bang ? ... : ...;` with:

~~~ts
      if (bang) return `<img src="${escapeHtml(url!)}" alt="${escapeHtml(label!)}">`;
      const text = emphasis(escapeHtml(label!));
      return allowedLink(url!) ? `<a href="${escapeHtml(url!)}">${text}</a>` : `<span>${text}</span>`;
~~~

## Is green enough?

Build the hostile course again and look for what is left:

~~~bash
pnpm start $HOSTILE $LAB/rung-5b
grep -rhoi 'href="[a-z]*script:[^"]*"\|src="data:[^"]*"' $LAB/rung-5b | sort -u
~~~

~~~
href="javascript:alert(document.cookie)"
src="data:image/svg+xml;base64,PHN2ZyBvbmxvYWQ9YWxlcnQoMSk+"
~~~

Two attacks still stand: the web link (its address never passes through Markdown) and the image. Your
requirement said "a link", and the code did exactly what the sentence said. The gap is in the sentence.

Now attack your own function. Browsers strip leading control characters from an address before reading its
scheme:

~~~bash
node -e 'import("./packages/lite/src/index.ts").then((m) => console.log(JSON.stringify(m.renderInline("[x](\u0001javascript:alert)"))))'
~~~

~~~
"<a href=\"\u0001javascript:alert\">x</a>"
~~~

A browser opens that as `javascript:`. The scenario is green, the gate is green, and the defence has a
hole. This is a **defect that escapes**: it passed every check you have.
