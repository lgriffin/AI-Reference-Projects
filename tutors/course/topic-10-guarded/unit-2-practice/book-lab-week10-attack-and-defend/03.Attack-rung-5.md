A red scenario says the rule is not kept. Now see what that means in a browser. Rung 6 carries a hostile
course as a fixture: a valid Tutors course whose author wants to run script in your readers' browsers.

export HOSTILE=$LADDER/variants/rung-6-guarded/tests/fixtures/hostile-course

Read every `.md`, `.marp` and `weburl` file. List what each tries. You should find at least: `javascript:`

## What escaping already stopped

~~~bash
grep -o '&lt;script&gt;[^<]*' $LAB/rung-5/topic-01-attack/unit-1-payloads/note-1-links/index.html
~~~

~~~
&lt;script&gt;alert(&#39;script-tag&#39;)&lt;/script&gt;
~~~

The raw tags are escaped text: rung 2's wall holds. So does the entity trick: `&#106;avascript:` became
`&amp;#106;avascript:`, which a browser reads as a harmless relative path.

## What escaping did not stop

~~~bash
grep -rhoi 'href="[a-z]*script:[^"]*"\|src="data:[^"]*"' $LAB/rung-5 | sort -u
~~~

~~~
href="JaVaScRiPt:alert%28%22mixed-case%22%29"
href="javascript:alert%28document.domain%29"
href="javascript:alert(document.cookie)"
href="vbscript:msgbox(1"
src="data:image/svg+xml;base64,PHN2ZyBvbmxvYWQ9YWxlcnQoMSk+"
~~~

Not one character in these needs escaping, so escaping leaves them alone.

## Click

Open `$LAB/rung-5/topic-01-attack/unit-1-payloads/note-1-links/index.html` in your browser. Click **the
reading list**, then **this one**. Go to the topic page (Up) and click **Course resources**. Each opens an
alert: the author's script is running in your page. In a deployed reader it would run with the reader's
session. This is **stored XSS**: stored, because the payload lives in the course and runs for every reader.
