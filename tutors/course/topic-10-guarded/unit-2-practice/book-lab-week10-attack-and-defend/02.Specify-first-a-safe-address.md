## The threat

A lecturer builds a course a colleague sent. One note holds this line:

~~~markdown
Click [the reading list](javascript:alert%28document.domain%29) to start.
~~~

Name the actor (the course author), the asset (the reader's browser and session) and the boundary (course
text into a page). Rung 5 has one rule on that boundary, R-008: "The site shall escape every piece of course
text that it writes into a page." Is the address above escaped? Does that help?

## 1. The requirement

~~~bash
pnpm test:ears:audit --next-id
~~~

~~~
R-022
~~~

A security rule is usually the **unwanted behaviour** pattern: "If *what an attacker supplies*, then the
*system* shall *what happens instead*." Write yours before you read on. Then compare it with this one, and
add a row to the table in `REQUIREMENTS.md`, after R-021:

~~~
| R-022 | Unwanted behaviour | If a link in a course has an address whose scheme is not http, https or mailto, then the site shall show its text without the address. | lite |
~~~

Did your sentence name what is **refused** ("starts with javascript:") or what is **allowed**? The first is
a block-list. Keep that question for step 4.

~~~

## 2. The Rule and two scenarios

Add to the end of `tests/bdd/features/site/static-site.feature` (two-space indent, the sentence word for
word). The first scenario is the attack. The second says what must survive the defence:

~~~gherkin

  @R-022 @ears-unwanted
  Rule: If a link in a course has an address whose scheme is not http, https or mailto, then the site shall show its text without the address.

    Scenario: A javascript link keeps its text and loses its address
      Given a course with a note whose Markdown is "[the reading list](javascript:alert)"
      When the site is built
      Then the note's page holds "the reading list"
      And no page holds "javascript:"

    Scenario: The addresses a course needs keep working
      Given a course with a note whose Markdown is "[a](https://tutors.dev) [b](mailto:hello@tutors.dev) [c](../topic-2/index.html#top)"
      When the site is built
      Then the note's page holds 3 links
~~~

## 3. The steps, and red

In `tests/bdd/steps/site/static-site.steps.ts`, add this Rule before the final `});`:

~~~ts
  Rule(
    "If a link in a course has an address whose scheme is not http, https or mailto, then the site shall show its text without the address.",
    ({ RuleScenario }) => {
      const noteIs = (_ctx: unknown, markdown: string) => {
        course = courseOf({ ...lo("note-1"), type: "note", contentMd: markdown });
      };

      RuleScenario("A javascript link keeps its text and loses its address", ({ Given, When, Then, And }) => {
        Given("a course with a note whose Markdown is {string}", noteIs);
        When("the site is built", built);
        Then("the note's page holds {string}", (_ctx, text: string) => {
          expect(page("note-1/index.html")).toContain(text);
        });
        And("no page holds {string}", (_ctx, text: string) => {
          for (const { path, html } of site) expect(html, path).not.toContain(text);
        });
      });

      RuleScenario("The addresses a course needs keep working", ({ Given, When, Then }) => {
        Given("a course with a note whose Markdown is {string}", noteIs);
        When("the site is built", built);
        Then("the note's page holds {int} links", (_ctx, count: number) => {
          expect(page("note-1/index.html").split("<a href=").length - 1).toBe(count + 2); // and Home and Up
        });
      });
    },
  );
~~~
