# A private course, and what we install (Apply, Analyse)

## A course that is not for everyone

A course with `auth: 1` in `properties.yaml` is for signed-in, enrolled readers only (upstream
`guides/RBAC.md`, "Auth Levels"). A static site has no sign-in.

~~~bash
mkdir -p $LAB/private
printf '# Private course\n\nFor enrolled readers.\n' > $LAB/private/course.md
printf 'auth: 1\n' > $LAB/private/properties.yaml
printf 'educators:\n  - your-github-login\nwhitelist:\n  - a-student\n' > $LAB/private/enrollment.yaml
pnpm -s start $LAB/private $LAB/rung-6-private; echo "exit $?"
~~~

~~~
/tmp/.../private is a private course (properties.yaml says auth: 1), so the reader shows it only to signed-in, enrolled readers (sign-in-required). A static site has no sign-in: anyone with its link could read it. Nothing was written. To build it for a host that adds its own access control, run again with --private; every page is then marked private and noindex.
exit 1
~~~

Build it on purpose, and look at what changes:

~~~bash
pnpm -s start --private $LAB/private $LAB/rung-6-private
grep -o '<meta name="robots"[^>]*><meta name="tutors-access"[^>]*>' $LAB/rung-6-private/index.html
~~~

~~~
wrote 1 pages, marked private, and tutors.json to /tmp/.../rung-6-private
<meta name="robots" content="noindex, nofollow"><meta name="tutors-access" content="private">
~~~

## Read the decision

`apps/cli/src/run.ts` asks `canView` in `packages/rbac/src/index.ts` about an anonymous reader
(`AnonymousSession` from `packages/identity`). Open `tests/unit/rbac/policy.test.ts`: the whole policy is
one table of ten rows. Find the row for `eve` on a private course with a whitelist.

Now change `auth: 1` to `auth: yes` in `$LAB/private/properties.yaml` and build again without `--private`.
The message says `properties.yaml says auth: yes`, and the course is still refused. Find `accessOf`, and
the two words for this behaviour in its comment.

## A poka-yoke

Open `packages/lite/src/site-builder.ts`. `buildSite(course, { access })` takes a second argument that
rung 5's did not. In `apps/cli/src/run.ts`, change `buildSite(course, { access: ... })` to `buildSite(course)` and run:

~~~bash
pnpm typecheck
~~~

~~~
apps/cli/src/run.ts(48,56): error TS2554: Expected 2 arguments, but got 1.
~~~

Nobody can build a site without saying who it is for. That is poka-yoke, mistake-proofing, and on the
Assertion Ladder it is L5: there is no test to forget, because the mistake does not compile. Undo with
`git checkout .`.

## The reader's notice

The gate's third browser test opens the private fixture in the reader and reads:

~~~
Private course: "private-course" is not shown, because it is for signed-in readers, and this reader has no sign-in.
~~~

Find `refusal` in `apps/reader/src/lib/course/course-service.ts`. Then answer honestly: the reader fetched
`tutors.json` in order to decide. Could a curious reader fetch it too? `RUNG.md` calls the notice "a
courtesy, not access control". Who holds the lock?

In `package.json`, change the `typescript` version to `"github:microsoft/TypeScript"` and run it again:

~~~
non-registry-source: package.json asks for "typescript" at "github:microsoft/TypeScript". Every dependency comes from the npm registry by version range (or is "@ladder/...": "workspace:*"), so the lockfile can pin it with an integrity hash and an audit can see it. A git URL, tarball, file: or link: path, or npm: alias bypasses both. Use a registry version, or ask a person (AGENTS.md).
~~~

Undo it. Then, if you are online, run `pnpm audit:online` and read what it reports. It is not in the Single
