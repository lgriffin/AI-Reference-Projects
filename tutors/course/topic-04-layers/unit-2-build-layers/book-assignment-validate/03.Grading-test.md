# The grading test

The grading test is in the variant: `variants/rung-3-layers/tests/assignment/validate-package.test.ts`.
Unlike rungs 1 and 2, the gate **does** reach it (`tests/**/*.test.ts`), so it is written to skip unless
you ask for it, and to compile before your package exists.

~~~bash
cd $LADDER/variants/rung-3-layers
LADDER_ASSIGNMENT=1 node --test tests/assignment/*.test.ts
~~~

Before you start, all seven fail. When you are done, `# pass 7`. Without the variable, `pnpm test` reports
them as `# skipped 7`.

## How it compiles before the package exists

`pnpm typecheck` checks the tests too (`tsc -p .`), and `@ladder/validate` does not exist yet. So the test
loads it at run time, from a path tsc does not follow:

~~~ts
/** The package's validate function, loaded at run time so this file compiles before the package exists. */
async function loadValidate(): Promise<Validate> {
  const index = join(PACKAGE, "src", "index.ts");
  assert.ok(existsSync(index), "Create packages/validate/src/index.ts, exporting validate(fs: FileSystemPort): Promise<Finding[]>.");
  const module: { validate?: Validate } = await import(pathToFileURL(index).href);
  assert.equal(typeof module.validate, "function", "packages/validate/src/index.ts must export a function named validate.");
  return module.validate!;
}
~~~

Its failures teach, as the architecture test's do: each names what to create or change.

## What it checks

| Test | How |
| --- | --- |
| AC1 | reads `packages/validate/package.json` and `tsconfig.json` |
| AC2 | reads the root `package.json`, `LAYERS` in the architecture test, and `PACKAGES` in the fence |
| AC3 to AC5 | runs `validate` on `MemoryFileSystem` courses and compares findings exactly |
| AC6 | runs `validate` on the shared fixture through `NodeFileSystem` |
| AC7 | runs `node apps/cli/src/main.ts validate` on the fixture and on a broken course, and reads the output |

The V003 case writes a course with a topic, a unit and a side that each lack a `.md`, and expects:

~~~ts
[
  { rule: "V003", severity: "error", path: "topic-01-a", message: V003("Topic", "topic") },
  { rule: "V003", severity: "error", path: "topic-02-b/side-1-y", message: V003("Side unit", "side") },
  { rule: "V003", severity: "error", path: "topic-02-b/unit-1-x", message: V003("Unit", "unit") },
]
~~~

## Compare with upstream

Run upstream's validator on the same broken course and compare the text:

~~~bash
mkdir -p /tmp/broken/topic-01-a/note-1 && printf '# C\n' > /tmp/broken/course.md && printf '# N\n' > /tmp/broken/topic-01-a/note-1/note.md
cd /tmp/broken && deno run -A $MONO/packages/jsr/tutors-cli/main.ts validate
~~~

~~~
error V003 topic-01-a: This Topic has no .md file, so its card has no title. Add one, like topic.md, whose first line is the title.
warn  V011 netlify.toml: This course has no netlify.toml, so Netlify won't know how to build and publish it. ...
1 error, 1 warning. Fix the errors before publishing.
~~~

Upstream also warns about the missing `netlify.toml` (V011). Your `validate` command should print the V003
line word for word.
