# Hints

One at a time. Try for ten minutes before you take the next.

## Hint 1: copy a package's skeleton

`packages/lite` is the closest shape: a `package.json` with `exports` and one `workspace:*` dependency, and a
`tsconfig.json` with `"types": []`. Copy both, rename, change the dependency to `@ladder/gen`. Run
`pnpm install` so pnpm links it.

## Hint 2: which layer?

`validate` reads courses through `gen`'s port and uses `gen`'s `folderKind`. It renders nothing and is not
the command line. So it sits beside `lite`, above `gen`: `may: ["@ladder/model", "@ladder/gen"]`. Write the
`job` sentence so that the next person who breaks the rule learns why.

## Hint 3: walking the course

You need recursion over `fs.list(dir)`: for each entry that is a folder, ask `folderKind(entry.name)`. If
it is `topic`, `unit` or `side`, list that folder, check for a file ending in `.md`, and recurse. Paths are
built with `joinPath` from `@ladder/gen`.

## Hint 4: the messages

Keep the messages in one object, as upstream's `messages.ts` does, and type `V003`'s argument as the three
composite kinds, not `string`. Then a `Record` of kind names cannot miss one (L5 again).

## Hint 5: the command

In `apps/cli/src/run.ts`, check `args[0] === "validate"` before the existing argument handling, and
return the exit code from a small `runValidate(folder)`. Remember to add `@ladder/validate` to
`apps/cli/package.json` (the Closure rule will remind you) and run `pnpm install`.

## Hint 6: the gate is red, the grading test green

Read the failure: it is almost certainly the Closure rule, the Port rule, or `tsc -p packages/validate`.
Each message says what to do. If `PACKAGES` in the fence or `LAYERS` is missing your package, the
grading test's AC2 says which file to change.
