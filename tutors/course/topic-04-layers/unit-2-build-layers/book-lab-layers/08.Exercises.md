# Exercises

## Exercise 1: an import cycle

Make `@ladder/model` import a type from `@ladder/gen`. Which rules fail? Would pnpm even let it install?
Upstream has a named rule for cycles between packages: find it in `.dependency-cruiser.cjs`.

## Exercise 2: a rule that cannot fail

Delete `"@ladder/lite"` from the `LAYERS` table in a scratch copy and run the architecture test. It is
green, and `lite` is no longer checked at all. Write a test that fails when a folder under `packages/` or
`apps/` is missing from `LAYERS`. Which pattern from the Assertion Ladder is that?

## Exercise 3: a ratchet for rung 3

Add a `tests/architecture/known-violations.txt` to a scratch copy and change `none(...)` so a violation
listed in the file is allowed, a new one fails, and a listed one that no longer occurs fails too. Use
upstream's `ratchet` and `describeRatchet` as your model.

## Exercise 4: a browser adapter

Rung 4 will run in a browser. Sketch a `FetchFileSystem` that implements `FileSystemPort` over HTTP for a
course published with a file listing. Which package does it belong in, which methods are hard, and what
does the Rung Fence say today?
