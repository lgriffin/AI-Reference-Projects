# Break the port

An agent fixing a bug in `gen` decides it is simpler to read the file directly. Add to
`packages/gen/src/course-builder.ts`, below the other imports:

~~~ts
import { readFileSync } from "node:fs";
~~~

## The first wall: the compiler

~~~bash
pnpm typecheck
~~~

~~~
packages/gen/src/course-builder.ts(10,30): error TS2591: Cannot find name 'node:fs'. Do you need to install type definitions for node? Try `npm i --save-dev @types/node` and then add 'node' to the types field in your tsconfig.
~~~

Read the suggestion at the end. It is the compiler's generic advice, and here it is **wrong**: adding
`node` to `packages/gen/tsconfig.json` would tear down the wall. That file is behind the Human Boundary in
`AGENTS.md` for exactly this reason.

## The second wall: the architecture test

~~~bash
node --test tests/architecture/architecture.test.ts
~~~

~~~
Port rule: only apps/cli touches node: modules, process, the console or the network. gen receives the world through ports: gen reads files through FileSystemPort (its `fs` argument) and reports through BuildOptions.warn; lite returns pages as data for apps/cli to write. The package's tsconfig.json has no Node types, so tsc rejects this too.
  packages/gen/src/course-builder.ts uses from "node:fs"
~~~

This message knows the design. It says what to use instead.

## Try the other platform calls

One at a time, add each of these inside a function in `packages/gen/src/course-builder.ts` and run the
architecture test: `console.log("debug")`, `process.cwd()`, `fetch("https://tutors.dev")`. Which rule
fails for each? Which of them does the Rung Fence also reject, and with which rung?
