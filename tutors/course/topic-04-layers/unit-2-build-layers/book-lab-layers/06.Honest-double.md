# Make the double lie

## A small lie

In `packages/gen/src/memory-file-system.ts`, change the root case of `exists`:

~~~ts
    if (target === "") return Promise.resolve(false);
~~~

~~~bash
node --test apps/cli/tests/file-system-port.contract.test.ts
~~~

~~~
# Subtest: FileSystemPort contract: NodeFileSystem
# Subtest: FileSystemPort contract: MemoryFileSystem
    not ok 3 - exists is true for the root, a folder and a file, and false otherwise
      expected: true
      actual: false
# pass 5
# fail 1
~~~

The same assertion passed for `NodeFileSystem` and failed for `MemoryFileSystem`. Without the contract,
`gen`'s memory-based tests would have gone on passing. Undo with `git checkout packages/gen`.

## A new adapter

Courses are often shared as zip files. Start an adapter for them in `packages/gen/src/zip-file-system.ts`:

~~~ts
/** A course inside a zip file. Not written yet: every call says so. */
import type { DirEntry, FileSystemPort } from "./file-system-port.ts";

export class ZipFileSystem implements FileSystemPort {
  list(_dir: string): Promise<DirEntry[]> {
    return Promise.resolve([]);
  }
  readText(path: string): Promise<string> {
    return Promise.reject(new Error(`${path}: no such file`));
  }
  exists(_path: string): Promise<boolean> {
    return Promise.resolve(false);
  }
}
~~~

~~~bash
pnpm test
~~~

~~~
not ok 40 - every FileSystemPort adapter runs the port contract
    Honest Double rule: every FileSystemPort adapter runs the same contract, so a test double cannot drift from the real thing. Add the adapter to ADAPTERS in apps/cli/tests/file-system-port.contract.test.ts.
# fail 1
~~~

Do what it says. Export `ZipFileSystem` from `packages/gen/src/index.ts`, import it in the contract test,
and add `["ZipFileSystem", () => new ZipFileSystem()]` to `ADAPTERS`. Run `pnpm test` again: now the
contract itself fails for `ZipFileSystem`, three times. That is the right state for an adapter that is not
written yet: the contract is its to-do list.

Where should a real zip adapter live? It would need a zip library and `node:fs`, so not in `gen`. Which
layer, and what would the fence say about the library? Undo everything with `git checkout .` and
`git clean -n` (then `-f` once the list is only your file).
