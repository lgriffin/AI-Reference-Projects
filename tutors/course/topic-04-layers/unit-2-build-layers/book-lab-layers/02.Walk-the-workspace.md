# Walk the workspace

## The packages and their links

~~~bash
pnpm -r ls --depth 0
~~~

~~~
@ladder/cli@1.0.0 .../apps/cli (PRIVATE)
dependencies:
@ladder/gen link:../../packages/gen
@ladder/lite link:../../packages/lite

@ladder/gen@1.0.0 .../packages/gen (PRIVATE)
dependencies:
@ladder/model link:../model

@ladder/lite@1.0.0 .../packages/lite (PRIVATE)
dependencies:
@ladder/model link:../model
~~~

`@ladder/model` has no dependencies. `link:` means a symbolic link, not a copy:

~~~bash
ls -l packages/gen/node_modules/@ladder apps/cli/node_modules/@ladder
~~~

~~~
packages/gen/node_modules/@ladder:
model -> ../../../model

apps/cli/node_modules/@ladder:
gen -> ../../../../packages/gen
lite -> ../../../../packages/lite
~~~

So `import type { Course } from "@ladder/model"` in `gen` resolves to `packages/model/package.json`, whose
`exports` points at `src/index.ts`. Edit `model` and `gen` sees it at once; there is no build step.

## What moved, and what did not

Rung 3 started from a copy of rung 2. Compare a file that moved into a package:

~~~bash
diff ../rung-2-lite/src/markdown.ts packages/lite/src/markdown.ts && echo same
diff ../rung-2-lite/src/site-builder.ts packages/lite/src/site-builder.ts
~~~

`markdown.ts` is the same. `site-builder.ts` changed in its imports, and it gained its **own**
`assertNever` at the bottom. Why? Where did it import `assertNever` from in rung 2, and which rule would
that import break now?
