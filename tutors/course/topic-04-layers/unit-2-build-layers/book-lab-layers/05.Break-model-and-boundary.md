# Break the model and the boundary

## The Model rule

Upstream's `packages/jsr/types` exports a list of kinds as a constant. Try the same in `model`:

~~~bash
echo 'export const LO_TYPES = ["course", "topic"];' >> packages/model/src/index.ts
node --test tests/architecture/architecture.test.ts
~~~

~~~
Model rule: packages/model holds only `export type` and `export interface`, and imports nothing, so it adds no code and no dependency to any layer. Put functions and constants in the layer that uses them (preOrder and folderKinds live in gen).
  packages/model/src/index.ts: export const LO_TYPES = ["course", "topic"];
~~~

Upstream's `types` package does export constants (`LO_TYPES`, `isLoType`). Rung 3 is stricter. Write two
sentences: what does "types only" buy rung 3, and what would allowing constants cost? Undo with
`git checkout packages/model`.

## The Package boundary rule

Import across packages by path, which skips the other package's `index.ts`:

~~~ts
// in packages/lite/src/site-builder.ts
import type { FileSystemPort } from "../../gen/src/file-system-port.ts";
~~~

~~~
Package boundary rule: a relative import may not leave packages/lite/src. Import another package by its name (@ladder/...) through its index.ts, and only if the layering rule allows it.
  packages/lite/src/site-builder.ts imports "../../gen/src/file-system-port.ts"
~~~

Notice that the Layering rule is silent here: it only reads `@ladder/` specifiers. That is why the
boundary rule exists. Upstream has the same pair: `no-cross-workspace-relative-import` beside the layer
rules in `.dependency-cruiser.cjs`. Undo with `git checkout packages/lite`.
