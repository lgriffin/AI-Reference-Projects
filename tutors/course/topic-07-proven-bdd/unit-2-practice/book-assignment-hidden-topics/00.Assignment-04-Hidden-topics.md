# Assignment 4: hidden topics

Rung 4's coding assignment (A4 in `course.md`), assessed at the **Create** level of Bloom's taxonomy. It
assesses module outcomes M6 (specify behaviour with EARS and Given/When/Then, and judge a suite by closure and
mutation score) and M4 (analyse a variant against upstream and diagnose why a check fails).

A lecturer can hide a topic without deleting it: `properties.yaml` lists it under `ignore`, and upstream's
generator writes the topic with `hide: true`, so the reader can leave it out of the course page while its
links keep working. Upstream states this as Rule 0266 in `tests/bdd/features/generator/course-json.feature`.

Your task is to bring that rule to rung 4, end to end, the way this week taught: Specify first (an EARS
requirement and a scenario, seen red), the implementation in the right layer, a property test that can fail,
and every mutation floor held. The code is about twenty lines. The proof is the work.

You may work with a coding agent. The requirement is yours to write and approve before any code is.
