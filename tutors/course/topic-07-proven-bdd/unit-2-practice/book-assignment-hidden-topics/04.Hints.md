# Hints

One at a time. Try for ten minutes before you take the next.

## Hint 1: the sentence

Event-driven, so it starts with "When". Upstream's Rule 0266 is a good model; change "tutors" to the
system name this rung's audit accepts. If the audit says `layer-mismatch`, check the "Implemented in"
column.

## Hint 2: where in gen

`buildCourse` in `packages/gen/src/course-builder.ts` already checks for `course.md` through the port.
After the course is built, check `fs.exists("properties.yaml")`, read it with `fs.readText`, and walk
`course.los`. Only the course's direct children are topics.

## Hint 3: the parser

Split the text into lines. Find the line that is exactly `ignore:` (trailing blanks allowed). Then take
lines that start with blanks, a dash and an id, and stop at the first line that does not. Test it on its
own first: `ignorepin: 1234` is not `ignore:`, and a list item with no `ignore:` above it is not in the
list.

## Hint 4: the scenario's Given

Build the files in the Given step, as the other Rules do with `memory(...)`. One topic folder per id, each
with a `topic.md`, and a `properties.yaml` whose list you write from the scenario's quoted string with
`list(...)`.

## Hint 5: the property

Generate unique topic ids, then a subset of them with `fc.subarray`. Write `properties.yaml` with another
key before and after `ignore:`, so the parser's stopping rule is exercised. Compare the hidden ids, sorted,
with the subset, sorted. The negative fixture: wrap `buildCourse` so it drops hidden topics, and expect
`fc.check(...).failed` to be true.

## Hint 6: the survivors

Expect Regex survivors on your parser: anchors (`^`, `$`) and quantifiers (`\s*`, `\s+`). Each one is a
question: should "x: ignore:" count? Should "ignore: [a]" count? Should an item with no indent count?
Answer each with a one-line unit test. If a survivor changes nothing you can observe, it is equivalent:
say so in your commit message rather than writing a test for it.
