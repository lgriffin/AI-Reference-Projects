# Name the rule (Evaluate, Create)

From week 6 every rule becomes a requirement written in **EARS**, with an id. Keep practising informally.

| Pattern | Shape |
| --- | --- |
| Ubiquitous | The `<system>` shall `<response>`. |
| Event-driven | When `<trigger>`, the `<system>` shall `<response>`. |
| State-driven | While `<state>`, the `<system>` shall `<response>`. |
| Unwanted behaviour | If `<condition>`, then the `<system>` shall `<response>`. |
| Optional feature | Where `<feature>`, the `<system>` shall `<response>`. |

## This week's rule

This week's rules are about the **code**, not the course. One way to write the direction rule:

> **R1.** The workspace shall let each package import only the workspace packages that its layer lists in
> `LAYERS`.
>
> **R2.** If a source file imports a workspace package that its layer does not list, then the architecture
> test shall fail with the layer's reason and a way to move the code.

R1 is ubiquitous: it always holds. R2 is unwanted behaviour: it says what happens when the rule is broken.
