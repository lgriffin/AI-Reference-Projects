# Break the layering (Analyse)

An agent working on `lite` wants the title parser from `gen`. Add this line as the **first import** of
`packages/lite/src/site-builder.ts` (just after the header comment):

~~~ts
import { parseMarkdown } from "@ladder/gen";
~~~

The architecture test is quick to run alone:

~~~bash
node --test tests/architecture/architecture.test.ts
~~~

## Read it like a contributor

1. Which rule? Which file? Why is it wrong? Find all three answers in the message alone.
2. The Closure rule offers a fix: add the dependency. **Do not take it.** It would make Closure green and
   leave Layering red. When two rules disagree about the fix, the one that names the reason wins.
3. The right fix: `lite` does not need `parseMarkdown`; the `Course` it receives already has titles.

## The gate stops sooner

Run `pnpm test` with the import in place. It stops at `tsc -p packages/lite`, before any test runs:

~~~
packages/lite/src/site-builder.ts(9,31): error TS2307: Cannot find module '@ladder/gen' or its corresponding type declarations.
~~~

`lite` has no such dependency, so pnpm linked no `@ladder/gen` into `packages/lite/node_modules`. Which of
the two failures, the compiler's or the test's, would tell a newcomer **why**?

Undo with `git checkout packages/lite`.
