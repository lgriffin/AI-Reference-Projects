# Build beyond (Create)

Rung 3 is a place to start, not to stop. Pick two of these. Each starts from the value it adds, so it is
pulled work with a reason, not code for its own sake. Work on a branch, keep `pnpm test` green, and keep
the arrows pointing inward.

1. **A rule that says "cycle".** Value: a contributor who makes a cycle learns the word and the fix at once.
   Add a test to `tests/architecture/architecture.test.ts` that finds a cycle between any two `LAYERS` and
   fails with a message naming both packages and the seam to invert. Changing `tests/architecture/` is a
   Human Boundary change: you make it, and you say why in the commit.
2. **A layer table that cannot go stale.** Value: a package added next month is checked from day one. Delete
   `"@ladder/lite"` from `LAYERS` in a scratch copy and run the architecture test: it is green
   (`# pass 27`), and `lite` is not checked at all. Write a test that fails when a folder under `packages/`
   or `apps/` is missing from `LAYERS`.
3. **A diagram from the code.** Value: the README never drifts. Write a small script under `scripts/` that
   prints the arrows from the `package.json` files as Mermaid or ASCII, and a test that compares it with the
   README's Architecture block.
4. **Your own package.** Value: a place for code that both `gen` and `lite` could use, without coupling
   them. Design (on paper first) a `@ladder/text` package for pure text helpers such as `assertNever`. Which
   layer does it sit in, what may import it, and is it worth the extra package?
