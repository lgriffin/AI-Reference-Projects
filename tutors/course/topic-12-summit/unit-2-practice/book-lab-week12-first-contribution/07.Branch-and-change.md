# Branch and change (Apply)

## 1. Fork and branch

Fork the repository on GitHub, add your fork as a remote, and branch from an up-to-date `main` using the
naming in CONTRIBUTING.md (`feature/`, `fix/`, `docs/`, `test/`, `refactor/`, `chore/`):

~~~bash
cd $MONO
gh repo fork tutors-sdk/tutors-mono-repo --remote --remote-name fork
git checkout main && git pull origin main
git checkout -b docs/walkthrough-root-layout      # yours: <type>/<short-description>
~~~

You compared against the pinned commit in step 2. You contribute against today's `main`. Run step 4's search
once more now that you are on it.

## 2. If your change needs a Rule: red first

Follow the skill's steps 3 to 5. Put the Rule you approved into the feature file nearest the change, bind it
in a steps file that calls `loadFeature("tests/bdd/features/<persona>/<name>.feature")` with a literal path,
and run:

~~~bash
pnpm test:bdd
~~~

It must fail on an assertion about the missing behaviour. The skill is exact about this: "A failure from a
typo, a missing import or an unbound step is not RED", and "a scenario that passes before the implementation
does not test the change; rewrite it".

## 3. The change

Start your agent with the session manifest. Ask for the smallest change that meets the expected result. For
the walkthrough fix, read `apps/reader/src/routes/+layout.ts` yourself first: the row in the table must
describe what that file does today, not only carry its new name. Its opening comment says the root load is
"universal, not a server load (Rule 0771)", while the walkthrough still says "Server side". So the fix is a
sentence, not a rename, and it restores what an existing Rule already states: no new Rule is needed. When the agent says it is done:

~~~bash
git diff --stat
git diff
~~~

- check every path against your fence;
- read every line of the diff;
- for each line, ask "could I explain this to the reviewer?" If not, ask the agent to explain it, or remove
  it.

The walkthrough fix should print one line:

~~~
 docs/COURSE-PAGE-WALKTHROUGH.md | 2 +-
 1 file changed, 1 insertion(+), 1 deletion(-)
~~~

## 4. Format only what you touched

Formatting follows `.editorconfig` and `.prettierrc`. Existing files have not been reformatted in bulk, so
never run `pnpm format` on the repository:

~~~bash
pnpm exec prettier --check docs/COURSE-PAGE-WALKTHROUGH.md     # your files only
~~~

## 5. Commit

Conventional commit style, from CONTRIBUTING.md. Types: `feat`, `fix`, `docs`, `test`, `refactor`, `chore`,
`security`, `perf`.

~~~bash
git commit -am "docs: name the root +layout.ts in the course page walkthrough"
~~~

Commit the Rule, scenarios and steps with the implementation, "so a reviewer sees the requirement change
beside the code that satisfies it".

**On rung 7.** Branch in `~/src/tutors-ladder`, see `pnpm test` fail on your new scenario, then make it pass.
