# Build beyond (Create)

You are expected to go further than one pull request. Pick at least one, and start it from the value it
adds: say in one line who is better off (student, lecturer, contributor or maintainer) and how they would
notice. Work pulled by a reason is not overproduction. Each of these is a fair choice for the capstone, A8.

1. **Climb the rule.** The walkthrough drift passed every check because the rule "the walkthrough names only
   files that exist" is at L2. Take the Rule you wrote in step 5 and make it true: a step, or a case in
   `tests/completeness/completeness.test.ts`, that reads the backticked repository paths in
   `docs/COURSE-PAGE-WALKTHROUGH.md` and fails with a Teaching Failure naming the path and the line. Decide
   first whether it deserves a Rule, and whether paths that are examples need a way out. Discuss the approach
   on an issue before you write it: this is larger than a good first issue.
2. **Delete a baseline line.** Open `guides/testing/TESTING-OVERVIEW.md`, section "Ratchets, baselines and
   quarantine", choose one of the nine baselines, and fix one line in it at a rung you have finished: a
   missing translation in `tests/completeness/known-gaps.txt` is the classic. Fix the problem, delete the
   line, run the tier.
3. **Report the week 1 finding.** In week 1's lab the generator crashed on a course with no
   `properties.yaml` (`course.properties.llm` in `packages/jsr/gen/src/utils/llms.ts`) while the validator
   called the same folder fine. Reproduce it on today's `main`, search for an existing report, and if there
   is none open an issue with the exact commands and output. A good bug report is a contribution. If you fix
   it, the Rule comes first: what shall the generator do when a course has no properties?
4. **Give the ladder something back.** Find one place where a variant has drifted from the upstream file it
   mirrors (each `RUNG.md` has the table), and correct the variant or its `RUNG.md`. The ladder is standard
   work too.
5. **A second pull request, one rung higher.** Choose an issue one rung above your first. Reuse your session
   manifest; change only the Task, the Rung and the two lists.

Bring one to the final class and be ready to explain every line of it.
