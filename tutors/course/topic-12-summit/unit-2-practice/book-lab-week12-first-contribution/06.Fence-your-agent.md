# Fence your agent with a session manifest (Create)

Every variant gave your agent an `AGENTS.md` to read and a Rung Fence it could not cross. The mono-repo has
neither. Write a session manifest: a short file you give your agent at the start of every session. Keep it
under 500 words, like every `AGENTS.md` on the ladder. Keep it out of your commits: put it outside the clone,
or list it in `.git/info/exclude`.

## Template

Open rung 7's `AGENTS.md` (`$SHIPPED/AGENTS.md`) beside this. The sections are the same on purpose.

~~~markdown
# Session manifest

## Task
Issue #<n>: <one sentence>. Expected result: <from the issue>. How to check: <from the issue>.

## Rung
Rung <k> (<name>). Upstream areas for this rung: <paths from RUNG.md>.
Work only at this rung. If the change seems to need anything from a higher rung, stop and say so.

## May touch
- <the files the issue names>
- their tests: <paths>
- at most one feature file under tests/bdd/features, holding the Rule I approved: <the Rule, word for word>

## Must not touch
- any other package or app
- .github/, release/, Dockerfile, deploy/, supabase/
- package.json dependencies, pnpm-lock.yaml
- baselines (known-*.txt), coverage floors, mutation floors; except deleting a line my fix makes obsolete
- any existing test, to make it pass

## Read first
CONTRIBUTING.md, sections "Testing Your Changes" and "What CI checks on your pull request".
If behaviour changes: .claude/skills/ears-gherkin-dev/SKILL.md, and follow its eight steps.

## Gate
pnpm lint && pnpm test && pnpm check
Report each command's result. Green on all three means done, not before.

## Ask a human first
- a new or upgraded dependency
- a change to any test you did not write in this session
- a change to anything listed in .github/CODEOWNERS
- any change to the wording of the Rule
~~~

## Fill it in

Write yours for the improvement you chose. For the walkthrough fix it is very short: "May touch" is one file,
`docs/COURSE-PAGE-WALKTHROUGH.md`, and the gate is the completeness tier
(`pnpm exec vitest run tests/completeness`), because the pull request template lets docs-only changes skip
the three checks.

## Check the fence yourself

There is no `tests/rung-fence.test.ts` here. Before every commit:

~~~bash
git diff --stat
~~~

Every path must be on the "May touch" list. If one is not, either the manifest was wrong (change it, on
purpose, and say why in the pull request) or the agent left your rung (revert that file). This is the Rung
Fence at L2, checked by a person instead of a test.

## Judge your manifest

Give it to a classmate with the issue, and ask: "From this page alone, what would you refuse to do?" If they
cannot name three things, the "Must not touch" list is too vague.

**On rung 7.** The variant's `AGENTS.md` and Rung Fence still apply. Your session manifest adds only the
Task, "May touch" and the approved requirement.
