# The A3

An A3 is one page that argues for a change. Week 11's readiness A3 answered "should we ship?". This one
answers "was this worth changing, and is it now fixed where it broke?". One side of A4 (or A3), about 400 to
600 words, with at most one diagram or table. Write it for a maintainer who has five minutes.

## The five sections

| Section | The question it answers | What a good one holds |
| --- | --- | --- |
| **1. Value** | Who is better off, and how would they notice? | one named customer (student, lecturer, contributor, maintainer, operator), the step of the Tutors value stream it improves, and why this change before any other |
| **2. Current state** | What happens today? | a command and its real output, or a screenshot, at a named commit; the rung the change sits on and the upstream paths involved; your value stream sketch with real times |
| **3. Root cause** | Why does it happen? | a Five Whys chain that ends at something changeable: a missing rule, a rule kept too low on the Assertion Ladder, a gap between two lists. Never a person |
| **4. Countermeasure** | What did you change, and why this and not more? | the Rule (id and sentence); the change in one sentence; the level the rule sat at before and after (L0 to L5) with the file that now keeps it; what you chose **not** to do |
| **5. Evidence** | How do we know it worked? | the red-then-green run or the before-and-after output; the gate results; `git diff --stat` beside "May touch"; the pull request link and its state; any review and your response |

End with one line of follow-up: the next small improvement, and who should own it.

## A worked skeleton

For the lab's walkthrough fix, filled in briefly. Yours must be about your own change.

~~~markdown
# A3: the course page walkthrough names the root layout that exists

**Value.** A new contributor reading docs/COURSE-PAGE-WALKTHROUGH.md, which CONTRIBUTING.md tells them to
read first. Today section 2 sends them to a file that is not there.

**Current state** (main at <sha>). `grep -n "layout.server" docs/COURSE-PAGE-WALKTHROUGH.md` prints line 48;
`ls apps/reader/src/routes | grep layout` prints +layout.svelte and +layout.ts. Rung: docs, weeks 1 and 2.
Lead time: claimed <date>, opened <date>, merged <date>; work 40 minutes, waiting <n> days.

**Root cause.** Why is the path wrong? The root load is universal now (Rule 0771, cited in +layout.ts) and the document
still describes a server load.
Why was the document not updated? Nothing told the author the document names that file. Why not? The
completeness tier checks links, not paths in backticks. Root cause: "the walkthrough names only files that
exist" is kept at L2.

**Countermeasure.** One row of the table corrected to name +layout.ts and say what it does now. Restores
Rule 0771's wording; no new Rule. Level after: still L2. Not done here: a check that would hold it at L3
(scratch Rule attached; proposed on issue #<n>), because it is a second, larger change.

**Evidence.** Before and after grep output; `pnpm exec vitest run tests/completeness`: 11 passed;
diff --stat: one file, on "May touch"; PR #<n>, one review round.

**Follow-up.** Propose the L3 check as its own pull request; owner: me, after discussion on the issue.
~~~

## How it is judged

The A3 is evidence for outcomes 2, 3 and 5. A strong A3 is honest about what did not go well: a fence that
did not hold, a gate you could not run, a review comment you had not foreseen. An A3 that reports no
difficulty at all is usually missing its current state.
