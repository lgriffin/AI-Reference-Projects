# Submission checklist

There is no grading test for the capstone. Submit one folder (or one document with links) holding the items
below, and tick each line yourself first. An unticked line is a conversation, not a failure: say why.

## What to submit

| Item | File or link | Criteria |
| --- | --- | --- |
| The A3 | `A3.pdf` or `A3.md`, one page | AC1, AC2, AC9, AC10, AC11 |
| The Rule and scenario | the feature file in the pull request, or `my-rule.feature` | AC3 |
| Audit output | `audit.txt` | AC4 |
| Red and green runs, or before and after output | `red.txt`, `green.txt` | AC5 |
| The session manifest | `session-manifest.md` | AC6 |
| The fence check | `diff-stat.txt` | AC7 |
| Gate output | `gates.txt` (the last lines of each command, and the Node version) | AC8 |
| The pull request | its URL, or `PR.md` on the rung 7 route | AC12 |
| Your Kaizen note from the lab | `kaizen.md` | supports the A3 |

## Before you submit

- [ ] I searched the issues and pull requests before claiming the work, and the issue is linked.
- [ ] The change sits on a rung I have finished, and the A3 names it.
- [ ] The Rule was written, and approved by me, before the code. The commit history or the red run shows it.
- [ ] The Rule has a system name, exactly one "shall", an id and one pattern tag.
- [ ] The audit reports no new violation (or only `unbound-feature` on a scratch Rule).
- [ ] My session manifest is under 500 words and has all seven sections.
- [ ] Every path in `git diff --stat` is on "May touch", or the A3 explains the exception.
- [ ] I ran the gates on the final commit, on the Node version the repository asks for.
- [ ] I loosened no test, baseline, floor or fence. Any baseline line my fix made obsolete is deleted.
- [ ] The pull request uses the template, ticks only what I ran, and says I worked with a coding agent.
- [ ] The A3 fits one page and has Value, Current state, Root cause, Countermeasure and Evidence.
- [ ] The root cause does not end at a person.
- [ ] The A3 says at which Assertion Ladder level the rule sat before and sits now, with the file.
- [ ] I can explain every line of the diff without the agent.

## The final class

Bring the A3 on paper. You will have five minutes to present it and five to answer questions, one of which
will be: "What is the next small improvement, and why have you not made it yet?"

## Exit criteria for the module

You have reached the Summit when you can say yes to each of these:

1. I can find the upstream home of any rung's capability without the map.
2. I can read a red check in tutors-mono-repo and say which Assertion Ladder level it sits at.
3. I can write a Rule a maintainer would approve, before I write code.
4. I can fence an agent in a repository that has no fence.
5. I have improved somebody else's standard work, by one small step, and left the gates as strict as I found
   them.
