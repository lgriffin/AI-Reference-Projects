## What this week adds

Rung 4 is a copy of rung 3 with the same product code and a new `tests/` tree:

- `REQUIREMENTS.md`: twelve requirements, `R-001` to `R-012`, each one EARS sentence with a pattern and a layer;
- `tests/bdd/`: three features whose `Rule:` titles repeat those sentences, bound with vitest-cucumber;
- `scripts/checks/ears-audit.ts`: the closure audit, run in the gate;
- Vitest in place of `node --test`, because Stryker (next week) needs it.

This week is about the sentence. Next week is about the scenario, properties and mutation testing, and ends
with rung 4's assignment.

## The value it delivers

Rung 4's customer is still the contributor, and now also the **reviewer**: a person can approve a short
sentence before any code exists, and the gate guarantees the code that follows is proved against it.
