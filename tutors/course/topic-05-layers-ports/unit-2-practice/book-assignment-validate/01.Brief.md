# The brief

## The two rules

From `packages/jsr/course-rules/src/finding.ts` (tutors-mono-repo `2b96b69`):

| Rule | Severity | Summary |
| --- | --- | --- |
| V001 | error | The course folder has a course.md |
| V003 | error | Every unit, side and topic has a descriptor .md |

From `packages/jsr/course-rules/src/messages.ts`:

~~~ts
V001: () => "This folder has no course.md, so Tutors can't tell it is a course. Add a course.md whose first line is the course title, like # Web Development.",
V003: (kind: string) => `This ${kindName(kind)} has no .md file, so its card has no title. Add one, like ${kind}.md, whose first line is the title.`,
~~~

where `kindName` gives `Unit`, `Side unit` and `Topic` for `unit`, `side` and `topic`. Upstream applies them
in `checkTree` and `checkFolder` in `packages/jsr/course-rules/src/validate.ts`, and tests their corners in
`tests/unit/course-rules/course-rules.test.ts` ("V003 covers units, sides and topics but not the root or
simple kinds").

## The package

Create `packages/validate`, named `@ladder/validate`, exporting from `src/index.ts`:

~~~ts
export type RuleId = "V001" | "V003";
export interface Finding {
  rule: RuleId;
  severity: "error";
  path: string;     // relative to the course root; "" is the root itself
  message: string;  // upstream's message, word for word
}
export function validate(fs: FileSystemPort): Promise<Finding[]>;
~~~

- It reads the course **only** through `FileSystemPort`, the port `@ladder/gen` already owns. It never
  touches `node:fs`.
- It decides a folder's kind with `folderKind` from `@ladder/gen`, so the validator and the generator agree
  on what a `topic-`, `unit-` or `side-` folder is.
- It walks every folder that names a composite kind, at any depth, and skips folders of no kind and simple
  kinds.
- It returns findings sorted by path, then by rule, as upstream's `sortFindings` does.

## The command

Make `apps/cli` run it: `node apps/cli/src/main.ts validate <courseFolder>` prints each finding as
upstream's `tutors validate` does, `<severity> <rule> <path>: <message>`, then a count, and exits 1 if
there is an error, 0 if not. The existing `<courseFolder> <outDir>` form must keep working.
