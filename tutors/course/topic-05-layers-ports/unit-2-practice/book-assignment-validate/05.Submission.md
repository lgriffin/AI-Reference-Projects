# Submission

Submit a link to a Git repository (or a zip of your `tutors-ladder/rung-3-layers` folder with its `.git`)
that adds `packages/validate` and the changes it needs, starting from the commit "rung 3, as shipped" you
made in Lab 4.

## Checklist

- [ ] `LADDER_ASSIGNMENT=1 node --test tests/assignment/*.test.ts` reports `# pass 7`
- [ ] `pnpm test` is green
- [ ] `pnpm-lock.yaml` is updated by `pnpm install`, and no `node_modules/` is committed
- [ ] the Human Boundary changes (architecture test, fence, root `package.json`) are **one commit of their
      own**, written by you, before the commit that adds the code
- [ ] your pull request description shows two violations you seeded in the new package (for example a
      `node:fs` import and an import of `@ladder/lite`) and the messages that caught them
- [ ] the `README.md` architecture diagram and the package table include `@ladder/validate`
- [ ] if you worked with a coding agent, your description says so, and confirms you can explain every line

## Marking

All parts are assessed at Create: you design a package and its place in the layers, and you prove it.

| Part | Weight |
| --- | --- |
| AC1 to AC7, by the grading test | 40% |
| AC8 and AC9: the architecture rules and the gate, with your `LAYERS` entry and its reason | 20% |
| the two seeded violations and their messages | 15% |
| the history: boundary changes first, then code | 10% |
| the README update | 15% |
