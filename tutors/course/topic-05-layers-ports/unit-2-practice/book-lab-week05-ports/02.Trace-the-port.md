# Trace the port (Understand)

Follow one call from the command line to a file on disk.

1. `apps/cli/src/main.ts`: two lines. What does it pass to `run`, and what does it do with the result?
2. `apps/cli/src/run.ts`: find the line that makes a `NodeFileSystem`. What is its one argument? Then find
   the call to `buildCourse`. What are its three arguments, and which one replaces `process.stderr`?
3. `packages/gen/src/file-system-port.ts`: the port. Which package owns it? Why is every method `async`?
4. `packages/gen/src/course-builder.ts`: find `fs.list` and `fs.readText`. Is there any `node:` import in
   this file?
5. `apps/cli/src/node-file-system.ts` and `packages/gen/src/memory-file-system.ts`: the two adapters. Which
   package is each in, and why?

## Run the core on memory

The core runs without a disk. Save this as `try-memory.ts` in the variant's root and run it:

~~~ts
import { buildCourse, MemoryFileSystem } from "./packages/gen/src/index.ts";

const fs = new MemoryFileSystem({
  "course.md": "# A course\nIn memory.\n",
  "topic-1/topic.md": "# First topic\nIts summary.\n",
  "topic-1/note-1/note.md": "# A note\nRead me.\n",
});
const course = await buildCourse(fs, "memory-course");
console.log(course.title, "/", course.los.map((lo) => `${lo.type}:${lo.title}`).join(", "));
~~~

~~~bash
node try-memory.ts
~~~

~~~
A course / topic:First topic
~~~

No file was read from disk. Delete `try-memory.ts` when you are done.
