# Name the rule (Evaluate, Create)

Next week you meet EARS properly, with ids, patterns and an audit. This is the last informal one.

## This week's rules

> **R1.** The generator shall read a course only through the `FileSystemPort` it is given.
>
> **R2.** When a class implements `FileSystemPort`, the architecture test shall require it to run the port
> contract against the same cases as `NodeFileSystem`.

## Your turn

Write, in your notes:

1. the Port rule as an **unwanted behaviour** sentence: "If a file outside `apps/cli` ..., then ... shall ...";
2. the contract's "exists" test as a **ubiquitous** sentence about every adapter.

Judge each sentence, yours and R1 and R2:

- One "shall"? Could a test decide it? Which test does today?
- Which word names the system that "shall" do something? Is it the code under test (the generator), or the
  thing that checks it (the architecture test)? Next week you will see why that choice matters.

Bring all your "Name the rule" sentences from weeks 1 to 5 to week 6. You will formalise them there.
