# Acceptance criteria

Written as EARS sentences: one "shall" each, with the trigger or state that makes it apply. Each is mapped
to the week's learning outcomes (topic descriptor, outcomes 1 to 5) and to the module outcomes in
`course.md` (M1 to M8). The whole assignment is assessed at **Create**: you add a capability the rung did not
have.

| Id | Criterion | Week outcome | Module outcome |
| --- | --- | --- | --- |
| AC1 | When a folder's name starts with `github`, the generator shall build it as a learning object of type `github`. | 1, 5 | M1, M3 |
| AC2 | The generator shall order a `github` object after `web` objects and before `archive` objects in its parent, using the upstream order 10. | 1, 5 | M3 |
| AC3 | When a `github` folder holds a `githubid` file, the generator shall set the object's `route` to the first line of that file, without a trailing carriage return. | 2, 5 | M1, M3 |
| AC4 | The generator shall give a `github` object the same `id`, `title`, `summary` and `route` that upstream `tutors build` writes, whether it sits in a topic or in a unit. | 2, 4, 5 | M3, M4 |
| AC5 | If a `github` folder has no `githubid` file, then the generator shall still build the object, with an empty `route`. | 5 | M3 |
| AC6 | When the type checker is run with the variant's `tsconfig.json`, it shall report no errors. | 1, 3 | M3 |
| AC7 | When `npm test` is run, the gate shall pass, with the Rung Fence and the conformance test unchanged. | 3, 5 | M2, M8 |
| AC8 | The generator shall no longer print "skipped ... github..." for a `github` folder. | 2 | M1 |

AC1 to AC5 are checked by the grading test. AC6 is `npx tsc -p .`. AC7 is the Single Gate. AC8 you show
by building the reference course (`node src/main.ts ~/src/tutors-reference-course out/reference.json`).
