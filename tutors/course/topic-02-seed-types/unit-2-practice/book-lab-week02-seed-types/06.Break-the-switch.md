# Break the switch on purpose (Analyse)

You will remove one `case` and watch two levels of the Assertion Ladder catch it.

## Install the checker without saving it

~~~bash
cd $LADDER/variants/rung-1-seed
npm install --no-save typescript@6 @types/node@22
npx tsc -p .
~~~

`tsc` prints nothing: the code type-checks. `--no-save` leaves `package.json` alone, so the Rung Fence stays
green (try `npm test`). `node_modules/` is in `.gitignore`.

## Remove a case

In `src/course-builder.ts`, delete these two lines from the `switch` in `buildLo`:

~~~ts
    case "note":
      return { ...base(folder, kind), type: kind };
~~~

## L5: the compiler

~~~bash
npx tsc -p .
~~~

~~~
src/course-builder.ts(120,26): error TS2345: Argument of type '"note"' is not assignable to parameter of type 'never'.
~~~

The `default:` branch is now reachable with `kind === "note"`, so `kind` is not `never` there, and the call
`assertNever(kind)` does not compile. The error names the missing kind.

## L3: the gate

The gate does not run `tsc` on this rung. Run it anyway:

~~~bash
npm test
~~~

~~~
# Error: unhandled learning object kind: note
not ok 1 - tests/conformance.test.ts
not ok 4 - children are ordered by kind, then by folder name
# pass 8
# fail 2
~~~

Type stripping ran the code without checking it, and `assertNever` threw at run time. Without that throw,
the function would have returned `undefined` and written a `tutors.json` with a hole in it.

Put the lines back (`git checkout src/course-builder.ts`) and run `npm test` again.
