# The brief

## Start

Copy `variants/rung-3-layers` to `variants/summit-composed`. Rung 3 is the common ancestor of rungs 4 to 7, so
every difference between it and each of them is a Rung Delta you will bring across.

## Compose, one rung at a time

Bring the rungs across in the order 4, 5, 6, 7. For each one:

1. Read its `RUNG.md`: the capability, the expertise, the upstream mirror table.
2. Diff it against rung 3 (`diff -r variants/rung-3-layers variants/rung-<k>-<name>`) to see its whole delta.
3. Widen the composed fence by exactly that rung's allowance. Do this yourself, in its own commit.
4. Bring the code and tests across. Resolve each conflict by asking how tutors-mono-repo solves the same
   problem: the mirror tables point you to the upstream files.
5. Run the gate. Commit only when it is green.

## Where the conflicts will be

Expect them where two rungs touch the same thing. For example:

- the reader (rung 4) renders author content, which the guarded rung (6) must sanitise; upstream, the card
  summary passes through `sanitizeHtml` in `packages/svelte/ui-primitives/src/utils/sanitize.ts`
- the proven rung (5) specifies behaviour; the reader's and guard's behaviour need specifying too
- the shipped rung (7) builds and releases; it must now build the reader and run every other rung's tests

Write down each conflict and how you resolved it. That list is part of your submission.

## What not to do

- Do not lift the fence to "anything goes". The composed fence allows the union of rungs 4 to 7, nothing more.
- Do not delete or weaken a test to make the composition pass. If two rungs' tests disagree, the
  disagreement is a design question: answer it in `RUNG.md`.
- Do not add Supabase, realtime or anything else that is "Summit only".
