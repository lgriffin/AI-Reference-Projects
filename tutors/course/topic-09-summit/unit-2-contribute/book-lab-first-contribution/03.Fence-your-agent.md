# Fence your agent with a session manifest

The mono-repo has no `AGENTS.md` or `CLAUDE.md`, and no rung fence. Write a session manifest: a short file you
give your agent at the start of every session. Keep it under 500 words. Keep it out of your commits: put it
outside the clone, or list it in `.git/info/exclude`.

## Template

~~~markdown
# Session manifest

## Task
Issue #<n>: <one sentence>. Expected result: <from the issue>. How to check: <from the issue>.

## Rung
Rung <k> (<name>). Upstream areas for this rung: <paths from RUNG.md>.
Work only at this rung. If the change seems to need anything from a higher rung, stop and say so.

## May touch
- <the files the issue names>
- their tests: <paths>
- at most one feature file under tests/bdd/features, and only after I approve the Rule

## Must not touch
- any other package or app
- .github/, release/, Dockerfile, deploy/, supabase/
- package.json dependencies, pnpm-lock.yaml
- baselines (known-*.txt), coverage floors, mutation floors; except deleting a line my fix makes obsolete
- any existing test, to make it pass

## Read first
CONTRIBUTING.md, sections "Testing Your Changes" and "What CI checks on your pull request".
If behaviour changes: .claude/skills/ears-gherkin-dev/SKILL.md, and follow its eight steps.

## Gate
pnpm lint && pnpm test && pnpm check
Report each command's result. Green on all three means done, not before.

## Ask a human first
- a new or upgraded dependency
- a change to any test you did not write in this session
- a change to anything listed in .github/CODEOWNERS
- an EARS Rule: show it to me and wait for a yes
~~~

## Check the fence yourself

Before every commit:

~~~bash
git diff --stat
~~~

Every path must be on the "May touch" list. If one is not, either the manifest was wrong (change it, on
purpose, and say why in the PR) or the agent left your rung (revert that file). This is the Rung Fence, held by
a person instead of a test.
