# Branch, specify, change

## Fork and branch

Fork the repository on GitHub, clone your fork (or add it as a remote), and branch from `main` using the
naming in CONTRIBUTING.md:

~~~bash
git checkout -b <type>/<short-description>   # feature/, fix/, docs/, test/, refactor/, chore/
~~~

## If behaviour changes: the Rule first

1. Search for the behaviour: `grep -rn "<keyword>" tests/bdd/features`. If a Rule already states it, change
   that Rule, keeping its id.
2. Get a free id: `pnpm test:ears:audit --next-id`. It only sees `main`, so search the open pull requests for
   `@rule-` and take an id none of them uses.
3. Write one `Rule:` with exactly one "shall", tagged `@rule-NNNN` and one `@ears-*` tag, with scenarios
   beneath it.
4. Run `pnpm test:bdd` and watch it fail. Then write the code that makes it pass.

`guides/testing/EARS-METHODOLOGY.md` and `.claude/skills/ears-gherkin-dev/SKILL.md` describe each step in
detail. You approve the Rule; the agent does not.

## The change

Start your agent with the session manifest. Ask for the smallest change that meets the issue's expected
result. When it is done:

- run `git diff --stat` against your fence
- read every line of the diff
- for each line, ask "could I explain this to the reviewer?" If not, ask the agent to explain it, or remove it

Formatting follows `.editorconfig` and `.prettierrc`. Format only the files you touch: `pnpm format:check`
lists drift; do not reformat the repository.
