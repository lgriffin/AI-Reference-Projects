## The rule

Take the issue only if its rung is one you have finished. If it spans two rungs, you need both. If it is
"Summit only", leave it for now: it needs Supabase or realtime knowledge that no rung teaches.

Then reread that rung's `RUNG.md` in `tutors/variants/`. Its upstream mirror table is your map of the files
around the change.

## Behaviour or not?

Decide now whether a student, lecturer or operator could observe the change.

- **Yes**: you need an EARS Rule in `tests/bdd/features` (step 4).
- **No** (a refactor, a docs edit, a fix that restores what an existing Rule already says): no new Rule.
