# Hints

Use one hint at a time. Try for ten minutes before you take the next.

## Hint 1: let the compiler lead

Add the type and put it in the union. Then run `npx tsc -p .` and do exactly what each error asks. You
should see two errors, one in `src/course-builder.ts` and one in `src/model.ts`. Read the talk "Unions and
never" again if the `never` error puzzles you.

## Hint 2: the error the compiler cannot give

With both errors fixed, run the grading test. AC2 passes, but AC1, AC3 and AC5 still fail. Why? Look for the word `github` in
`src/model.ts`. One line still says it is a kind "this rung does not build". The type checker accepts it,
because `null` is a valid value in that table.

## Hint 3: the order

The `Record<LoType, number>` error tells you **that** `github` needs an order, not **which**. Upstream's
`preOrder` in `packages/jsr/model/src/types/type-utils.ts` has the number.

## Hint 4: the shape of the case

The `web` case already reads a one-line link file into `route`. Yours is the same with a different file
name. Keep the `satisfies` style if you like: `satisfies Github` makes the compiler check the object you
return against the new type.

## Hint 5: the carriage return

The second `githubid` in the grading test ends in `\r\n`. Split on `\n`, take the first line and remove the
`\r` (upstream) or trim it (as the `web` case does). Both agree on this input.

## Hint 6: still stuck

Compare your `buildLo` with upstream's `buildGithub` and `getGitLink`, quoted in the brief, line by line.
The whole change is about ten lines across two files.
