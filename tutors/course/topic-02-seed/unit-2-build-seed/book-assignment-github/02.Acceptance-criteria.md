# Acceptance criteria

Written as EARS sentences: one "shall" each, with the trigger or state that makes it apply.

| Id | Criterion |
| --- | --- |
| AC1 | When a folder's name starts with `github`, the generator shall build it as a learning object of type `github`. |
| AC2 | The generator shall order a `github` object after `web` objects and before `archive` objects in its parent, using the upstream order 10. |
| AC3 | When a `github` folder holds a `githubid` file, the generator shall set the object's `route` to the first line of that file, without a trailing carriage return. |
| AC4 | The generator shall give a `github` object the same `id`, `title`, `summary` and `route` that upstream `tutors build` writes, whether it sits in a topic or in a unit. |
| AC5 | If a `github` folder has no `githubid` file, then the generator shall still build the object, with an empty `route`. |
| AC6 | When the type checker is run with the variant's `tsconfig.json`, it shall report no errors. |
| AC7 | When `npm test` is run, the gate shall pass, with the Rung Fence and the conformance test unchanged. |
| AC8 | The generator shall no longer print "skipped ... github..." for a `github` folder. |

AC1 to AC5 are checked by the grading test. AC6 is `npx tsc -p .`. AC7 is the Single Gate. AC8 you show
by building the reference course (`node src/main.ts ~/src/tutors-reference-course out/reference.json`).
