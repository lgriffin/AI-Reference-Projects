# Build it with upstream

The oracle was written by upstream. Write it again yourself, so you trust it.

The upstream generator works in the current folder and writes `json/` there, so build a copy of the fixture:

~~~bash
rm -rf /tmp/ladder-fixture
cp -r ../fixtures/ladder-sample-course /tmp/ladder-fixture
cd /tmp/ladder-fixture
deno run -A $MONO/packages/jsr/tutors-cli/main.ts build
~~~

~~~

--: topic-01-basics : Basics
----: side-resources : Resources
------: archive-1-solutions : Solutions
----: unit-1-intro : Introduction
------: note-1-reading : Reading Guide
------: talk-1-welcome : Welcome
--: topic-02-practice : Practice
----: unit-1-lab : Hands On
------: book-1-first-lab : Objectives
------: web-1-tutors : Tutors
tutors: 5.3.0
~~~

You may also see warnings about a `vitest-cucumber` bin. They are harmless.

## Read the upstream log

The log is printed by `buildLo` in `packages/jsr/gen/src/services/course-builder.ts`, one line per folder,
in **folder** order, before sorting. That is why the note is listed before the talk here. It also prints the
lab as `Objectives`: the title from its first step's heading, before `buildLab` replaces it with the short
title because the lab has `img/main.png`.

## Compare

~~~bash
node ~/ladder-tools/outline.mjs json/tutors.json $LADDER/variants/fixtures/ladder-sample-course.tutors.json
~~~

Every line is `=`, except the first: the course's `id` is the folder's name, and your copy is called
`ladder-fixture`. Upstream writes `tutors.json` on one line (`JSON.stringify(lo)` in
`packages/jsr/gen/src/tutors.ts`). Rung 1 indents it; the data is the same.

## Look at what rung 1 leaves out

Open `json/tutors.json` and find the fields rung 1 does not write: `frontMatter`, `img`, `imgFile`, `video`,
`videoids`, `hide`, `authLevel`, and the course's `properties`. Each is in `RUNG.md`, "Deliberately left out".
