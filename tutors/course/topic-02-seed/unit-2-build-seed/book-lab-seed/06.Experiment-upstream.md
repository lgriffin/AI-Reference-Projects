when there is no `course.md`, and what exit status does it return?

## 2. A folder of no kind

Rename the note so its name has no kind, then build and validate:

~~~bash
mv topic-01-basics/unit-1-intro/note-1-reading topic-01-basics/unit-1-intro/reading
deno run -A $MONO/packages/jsr/tutors-cli/main.ts build
deno run -A $MONO/packages/jsr/tutors-cli/main.ts validate
~~~

The build log simply has no `note-1-reading` line. The note is gone, silently. The validator says why:

~~~
error V002 topic-01-basics/unit-1-intro/reading: The folder "reading" won't appear in your course, nor will anything inside it, because its name doesn't start with a kind Tutors knows (topic, unit, talk, note, lab and so on). Rename it to topic-reading.
1 error, 0 warnings. Fix the errors before publishing.
~~~

Rung 1 does the same: `folderKind("reading")` is `undefined`, and `children` skips it. Find the line. Then
find `namesItsKind` in upstream `packages/jsr/gen/src/services/resource-builder.ts`, which does the same job.
Rename the folder back.

## 3. Where upstream lets a kind slip

Open `packages/jsr/gen/src/services/course-builder.ts` and find `buildSimpleLo`. Its `switch` ends in
`default:` with nothing after it. Open `packages/jsr/model/src/types/learning-objects.ts`: `Lo.type` is a
`string`. Write down what would happen upstream if someone added `"slides"` to `simpleTypes` and forgot a
`case`. Then compare `packages/jsr/types/src/learning-objects.ts`, which derives `LoType` from an `as const`
list.

## 4. A crash worth reporting

Remove `properties.yaml` and build again:

~~~bash
rm properties.yaml
deno run -A $MONO/packages/jsr/tutors-cli/main.ts build
~~~

~~~
error: Uncaught (in promise) TypeError: Cannot read properties of undefined (reading 'llm')
  const llm = course.properties.llm as unknown as number;
    at generateLlms (.../packages/jsr/gen/src/utils/llms.ts:81:33)
    at generateDynamicCourse (.../packages/jsr/gen/src/tutors.ts:54:3)
~~~

`ls json` shows `tutors.json` was written before the crash, but `copyAssets` never ran. Read `buildCourse`
in `course-builder.ts`: `course.properties` is only set when `properties.yaml` exists. Rung 1 reads no
properties, so it cannot crash here. Is a course without `properties.yaml` valid? Run `validate` and see
whether any rule says so. This is the kind of finding the Summit topic turns into a first issue.
