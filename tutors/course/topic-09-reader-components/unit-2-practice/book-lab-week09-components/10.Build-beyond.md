# Build beyond (Create)

Pick two. Each starts from a student's need, so each starts with "Specify first": the next id, the EARS
sentence, a Rule with a scenario, red, then code, then a browser test if a student can see it. Stay inside
the fence: no new dependency, no server code, no storage.

1. **Mark the place.** Value: a student on the wall of labs can see which wall they are on. Mark the
   current wall link in the top bar with `aria-current="page"`. Split the rule first: what is decided, and
   what is displayed? Prove the decision by a scenario and the mark in the browser.
2. **Unit crumbs.** Value: a student deep in a long topic can jump back to the unit. `breadCrumbs` skips
   units because a unit has no page. Make a unit's crumb link to its box on the topic page (`Units.svelte`
   gives each box `id={unit.id}`). This changes R-021, so decide on purpose: amend it, or add a
   requirement beside it?
3. **A lab remembers nothing, on purpose.** Value: a student returning to a lab wants the step they left.
   The fence forbids browser storage at this rung. Without lifting it, what can you do with the URL alone?
   Write the requirement, and write down what you would need from rung 6 to do more.
4. **Keys for the pager.** Value: a student reading with the keyboard. After the assignment, add
   `Alt+ArrowRight` for the next learning object. Mind the lab, which already uses the plain arrows, and
   the guard in `navigateStep` against keys typed in inputs. Which tier proves it?
5. **Negative fixtures for the reader's layers.** Value: the next contributor can trust the layering rule.
   As upstream's `dependency-rules.test.ts` does, make `reader-layers.test.ts` prove each rule can fail on
   a small fixture. This changes `tests/architecture/`, which is yours to change and not your agent's: do
   it in a commit of its own, with the reason.

For each one, write first who asked for it and what they can do afterwards. If you cannot, do not build it.
