## Take away a `$derived`

In `apps/reader/src/lib/ui-components/structure/Composite.svelte`, change

~~~ts
  const { units, sides, standardLos } = $derived(arrange(composite));
~~~

to

~~~ts
  const { units, sides, standardLos } = arrange(composite);
~~~

Before you run anything, predict: when would a student see the wrong cards? (Hint: SvelteKit keeps a page's
components when the route folder stays the same and only a parameter changes. Today no link in the reader
goes from one topic straight to another, so you may not be able to show it by clicking. That is how such a
defect sleeps until a feature wakes it: a "next topic" link would.) Then:

~~~bash
pnpm typecheck
~~~

~~~
... WARNING "src/lib/ui-components/structure/Composite.svelte" 14:49 "This reference only captures the initial value of `composite`. Did you mean to reference it inside a closure instead?\nhttps://svelte.dev/e/state_referenced_locally"
... COMPLETED ... FILES 0 ERRORS 1 WARNINGS 1 FILES_WITH_PROBLEMS
~~~

The command fails, because the reader's `check` script is `svelte-check --fail-on-warnings`. So the gate
is red on a warning. Put `$derived` back (`git checkout .`).

Upstream turns this warning off for every app:

~~~bash
grep -n "state_referenced_locally" $MONO/packages/svelte/app-config/src/svelte.js
~~~

~~~
98:      if (warning.code === 'state_referenced_locally') return;
~~~

Write two sentences: why might a large, long-lived codebase choose that, and what does it cost?

## Shared state

~~~bash
grep -rn "currentCourse.value\|currentLo.value" apps/reader/src | grep -v "^apps/reader/src/lib/runes"
~~~

Sort the lines into two lists: who **writes** (`... .value = ...`) and who **reads**. You should find that
only `+page.ts` files write, and only navigators and the course layout read. Data flows one way: URL,
load, rune, shell.

## What a rune hands back

In `apps/reader/src/routes/(course-reader)/topic/[courseid]/[...loid]/+page.ts`, add one line after
`currentLo.value = topic;`:

~~~ts
  console.log("same object?", currentLo.value === topic, "same title?", currentLo.value?.title === topic.title);
~~~

Open a topic page with the browser's console open:

~~~
same object? false same title? true
~~~

You stored `topic` and read back something that is not `topic`: a reactive proxy of it. Every property
reads through, so almost nothing notices. Remove the line (`git checkout .`), and remember the result. You
will need it in step 5.
