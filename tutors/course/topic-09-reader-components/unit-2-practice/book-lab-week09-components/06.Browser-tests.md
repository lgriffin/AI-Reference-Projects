`tests/e2e/smoke.e2e.ts` and `tests/e2e/serve.ts` first: forty lines of test, thirty of server.

Three things to notice in the smoke test:

- it finds things as a person would, by role and name: `page.getByRole("link", { name: "Open the course" })`;

A route is a string, and two equal strings are equal on either side of a proxy. Make `pageTitle` take the
route:

~~~ts
/**
 * The browser tab's title for the page at this route: the page, then the pages above it, ending at the
 * course (R-023). It takes the route, not the object: a rune hands back a reactive proxy of what it was
 * given, and `parents` is keyed by the tree's own objects, so a proxy would have no parent.
 */
export function pageTitle(tree: CourseTree, route: string): string {
  const lo = findLo(tree, route);
  return lo ? breadCrumbs(tree, lo).map((crumb) => crumb.title).reverse().join(" | ") : tree.course.title;
}
~~~

In the layout, pass `currentLo.value.route`:

~~~svelte
  <title>{currentCourse.value && currentLo.value ? pageTitle(currentCourse.value, currentLo.value.route) : "Tutors ladder reader"}</title>
~~~

In the steps, the `Then` becomes one line:

~~~ts
          expect(pageTitle(course!, path)).toBe(expected);
~~~

and the unit test changes to routes, with one more case for the new branch:

test("a page's title runs from the page back to the course", () => {

  assert.equal(pageTitle(tree, "/course/sample"), "Ladder Sample Course");
  assert.equal(pageTitle(tree, "/wall/lab/sample"), "Ladder Sample Course", "a route with no page of its own is titled by its course");
