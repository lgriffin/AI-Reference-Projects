# Specify first: a page title (Evaluate, Create)

## The need

Open three tabs: the course page, a lab step, and your wall of labs from last week. Read the tab titles.

| Page | Tab title today |
| --- | --- |
| `/course/ladder-sample-course` | `Ladder Sample Course \| Ladder Sample Course` |
| `/topic/ladder-sample-course/topic-01-basics` | `Basics \| Ladder Sample Course` |
| `/note/.../note-1-reading` | `Reading Guide \| Ladder Sample Course` |
| `/wall/lab/ladder-sample-course` | `Ladder Sample Course \| Ladder Sample Course` |

A student with ten tabs open reads titles to find their place. The course page says its name twice, and a
note does not say which topic it belongs to. Nobody specified the title, so nobody decided. Find where it
is made:

~~~bash
grep -n "<title>" 'apps/reader/src/routes/(course-reader)/+layout.svelte'
~~~

~~~
18:  <title>{[currentLo.value?.title, currentCourse.value?.course.title].filter(Boolean).join(" | ")}</title>
~~~

A rule, living in a layout, proved by nothing. Apply the method from the second reading note:

- **What is decided?** Which titles, in which order. The reader already knows a page's ancestors: its
  breadcrumbs (R-021).
- **What is displayed?** The document's `<title>`. Only a browser can observe that.

## 2. The Rule and its scenarios

At the end of `tests/bdd/features/reader/reader.feature`:

~~~gherkin
  @R-023 @ears-ubiquitous
  Rule: The reader shall title each page with the titles of its breadcrumbs, from the page on screen back to the course.

    Scenario: A note names itself, its topic and its course
      Given upstream's tutors.json for the shared fixture, read as the course "sample"
      Then the title of "/note/sample/topic-01-basics/unit-1-intro/note-1-reading" is "Reading Guide | Basics | Ladder Sample Course"

    Scenario: The course page names the course once
      Given upstream's tutors.json for the shared fixture, read as the course "sample"
      Then the title of "/course/sample" is "Ladder Sample Course"
~~~

The second scenario is the defect you saw, written down as the behaviour you want.

## 3. Bind the steps

In `tests/bdd/steps/reader/reader.steps.ts`, add `pageTitle` to the import from `lo-tree.ts`, and add
before the file's last line:

~~~ts
  Rule("The reader shall title each page with the titles of its breadcrumbs, from the page on screen back to the course.", ({ RuleScenario }) => {
    for (const title of ["A note names itself, its topic and its course", "The course page names the course once"]) {
      RuleScenario(title, ({ Given, Then }) => {
        Given("upstream's tutors.json for the shared fixture, read as the course {string}", decorated);
        Then("the title of {string} is {string}", (_ctx, path: string, expected: string) => {
          const lo = findLo(course!, path);
          expect(lo, `no page at ${path}`).toBeDefined();
          expect(pageTitle(course!, lo!)).toBe(expected);
        });
      });
    }
  });
~~~

It is modelled on the breadcrumbs Rule just above it: find the page, ask the logic.
