# Make it green, then look (Apply, Analyse)

## 1. The logic, test first

Add a unit test to the end of `tests/unit/reader/lo-tree.test.ts` (and `pageTitle` to its import):

~~~ts
// Added in Lab 9 with R-023.
test("a page's title runs from the page back to the course", () => {
  const note = findLo(tree, "/note/sample/topic-01-basics/unit-1-intro/note-1-reading")!;
  assert.equal(pageTitle(tree, note), "Reading Guide | Basics | Ladder Sample Course");
  assert.equal(pageTitle(tree, tree.course), "Ladder Sample Course");
});
~~~

Then the function, at the end of `apps/reader/src/lib/course/lo-tree.ts`. It is `breadCrumbs`, turned
round:

~~~ts
/** The browser tab's title: the page on screen, then the pages above it, ending at the course (R-023). */
export function pageTitle(tree: CourseTree, lo: Lo): string {
  return breadCrumbs(tree, lo).map((crumb) => crumb.title).reverse().join(" | ");
}
~~~

## 5. Find out why

Do not guess. You have the evidence already.

1. The scenario calls `pageTitle(course, lo)` with a page from `findLo`. It passes. So `pageTitle` is right
   for the objects in the tree.
2. The layout calls `pageTitle(currentCourse.value, currentLo.value)`. What did step 3 of this lab show
   about `currentLo.value`?
3. `pageTitle` calls `breadCrumbs`, which walks `tree.parents.get(at)`. What kind of thing is `parents`,
   and what is it keyed by?

Write the cause down in one sentence before reading on.

The cause: `currentLo.value` is a proxy of the page, and `parents` is a `Map` keyed by the page itself.
`tree.parents.get(proxy)` is `undefined`, so the walk stops after one crumb. Nothing is wrong with the
function. It is given an object whose **identity** was changed on the way.

Ask "why?" a few more times, as in week 5:

- Why was the scenario green? It handed the function a plain object. A scenario over plain logic has no
  runes in it.
- Why did the types not catch it? A proxy of a `Lo` is a `Lo` to TypeScript.
- Why does `SecondaryNavigator`, which also calls `breadCrumbs`, work? Its `lo` arrives as a prop from the
  page's `data`: the original object, never through a rune.
- Why was nothing stopping you? "Compare values, not objects, across a rune" is a rule this reader keeps
  only by example (L1).

Do **not** fix it yet, and do not commit. You found this defect by looking. The next step first makes the
looking automatic, then fixes the cause.
