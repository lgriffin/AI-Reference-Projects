# Hints

Take one at a time. Each says a little more than the last.

1. **Start with the sentence.** Which EARS pattern? There is a trigger ("when a talk, a note or a lab is
   shown"), so Event-driven fits, as it did for R-019, the lab's step links. Read R-019 again: your rule is
   its cousin, one level up.
2. **Where is the order already?** `decorateCourseTree` in `lib/course/lo-tree.ts` walks the course once,
   in pre-order, and fills `loIndex` as it goes. A `Map` keeps insertion order. Your `wall` from Lab 8 used
   the same fact.
3. **Which kinds are stops?** `loIndex` holds pages: course, topics, talks, notes and labs. Filter it to
   `talk`, `note` and `lab`, and you have `readingOrder`.
4. **Neighbours, by value.** Find the learning object's place in that list by its `route`, not by `===`.
   You know why from Lab 9, step 5: the component will read the course from a rune. Previous is
   `index - 1`, next `index + 1`. Not found means no neighbours.
5. **Write the tests first.** `tests/unit/reader/lo-tree.test.ts` shows how to load upstream's file and
   decorate it. Assert the three titles, then the first, a middle and the last stop, then the course page.
   The scenarios can reuse the `Given` "upstream's tutors.json for the shared fixture, read as the course
   {string}" and need one new `Then`.
6. **The component.** `LoPager.svelte` takes `lo` with `$props()`, reads `currentCourse.value` from
   `lib/runes`, and computes `{ previous, next }` with `$derived`. `SecondaryNavigator.svelte` has the same
   shape; the lab's "Step pager" has the markup.
7. **Placing it.** Import it in `Note.svelte` and `Lab.svelte` and render `<LoPager lo={...} />` after the
   content. The Reader layering rule lets `ui-components` import `ui-navigators`. It does not let
   `ui-primitives` do so, so do not put the pager there.
8. **The mutation floor.** Add the file to `mutate` in `stryker.config.json`. `pnpm test` now fails with
   the Mutation floor rule. Run `pnpm test:mutation`, read the row for `lo-pager.ts`, kill any survivor
   with a unit test (remember that scenarios are not in the mutation run), then
   `pnpm check:mutation-floors --update`.
9. **Two pagers on a lab.** Give yours `aria-label="Learning object pager"`; the lab's own is
   "Step pager". Run `pnpm test:e2e` to see that the smoke test still finds its links: it looks for a link
   named "Setup →", and your pager must not add a second link with that name.
