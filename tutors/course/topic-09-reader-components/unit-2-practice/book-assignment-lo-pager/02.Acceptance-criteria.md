# Acceptance criteria

EARS sentences, one "shall" each. Each criterion maps to a week 9 outcome and a module outcome. All are
assessed at **Create**, because together they are a feature you specify, design, build and prove.

| Id | Criterion | Week 9 outcome | Module outcome |
| --- | --- | --- | --- |
| AC1 | `REQUIREMENTS.md` shall state the reading-order rule as one EARS requirement for the reader, with the next id, written before the code. | Specify a UI behaviour first | M6 |
| AC2 | A `Rule:` in `tests/bdd/features/reader` shall prove that requirement with at least one scenario, with the EARS audit reporting no finding. | Specify first; judge the suite by closure | M6 |
| AC3 | `readingOrder(tree)` shall return the course's talks, notes and labs, in the order `tutors.json` holds them. | Design and build a navigator | M3 |
| AC4 | `loNeighbours(tree, lo)` shall return the stops before and after `lo`, leaving out the one that an end of the course does not have, and neither for a page that is not a stop. | Design and build a navigator | M3 |
| AC5 | The logic shall be `apps/reader/src/lib/course/lo-pager.ts` with unit tests in `tests/unit/reader/lo-pager.test.ts`, and the component shall be `apps/reader/src/lib/ui-navigators/LoPager.svelte`, shown by `Note.svelte` and `Lab.svelte`. | Explain the three UI layers | M3 |
| AC6 | Stryker shall mutate `lo-pager.ts`, the file shall have a floor, and a fresh mutation report shall meet every floor. | Judge the suite by mutation score | M6 |
| AC7 | When a student pages from the first talk in a browser, the navigation named "Learning object pager" shall lead through the note to the lab, with one link at each end. | Prove a behaviour in a browser | M6 |
| AC8 | When `pnpm test` is run, the gate shall pass, with the fence, the architecture tests and every earlier requirement unchanged. | all | M2 |
| AC9 | When `pnpm test:e2e` is run, the smoke test shall still pass. | Diagnose which check catches a change | M6 |

AC1 to AC6 are checked by `tests/assignment/lo-pager.grading.test.ts`, AC7 by
`tests/assignment/lo-pager.e2e.ts`. AC8 and AC9 are the variant's own gates. A person reads your
requirement, your scenarios and your unit tests: the sentence should have one "shall" and an observable
response; the scenarios should cover a middle stop, an end and a non-stop; the unit tests should leave no
mutant alive in `lo-pager.ts` that is not equivalent.
