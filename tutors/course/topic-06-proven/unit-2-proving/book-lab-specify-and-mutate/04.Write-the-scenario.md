# Write the scenario

## The Rule

Append to `tests/bdd/features/site/static-site.feature`, indented like the Rules above it:

~~~gherkin
  @R-013 @ears-event-driven
  Rule: When a lab has more than one step, the site shall label each step page with its position, such as Step 2 of 3.

    Scenario: Each step knows where it is
      Given a course with a lab whose steps are "Intro, Setup, Build"
      When the site is built
      Then the step page "Setup.html" says "Step 2 of 3"
~~~

~~~bash
pnpm test:ears:audit    # EARS audit: every requirement is proved, and every citation is known.
pnpm test:bdd
~~~

The audit is satisfied: the Rule exists and has a scenario. vitest-cucumber is not:

~~~
RuleNotCalledError: Rule: When a lab has more than one step, the site shall label each step page with its
position, such as Step 2 of 3. was not called
~~~

## Bind the steps

In `tests/bdd/steps/site/static-site.steps.ts`, add a `Rule` before the final `});` of `describeFeature`.
The Given and When steps are the same as R-010's, so reuse them:

~~~ts
  Rule("When a lab has more than one step, the site shall label each step page with its position, such as Step 2 of 3.", ({ RuleScenario }) => {
    RuleScenario("Each step knows where it is", ({ Given, When, Then }) => {
      Given("a course with a lab whose steps are {string}", (_ctx, names: string) => {
        const steps: Lab["los"] = list(names).map((name) => ({ type: "step", id: name, shortTitle: name, title: name, contentMd: `# ${name}`, route: "" }));
        course = courseOf({ ...lo("book-1"), type: "lab", los: steps });
      });
      When("the site is built", built);
      Then("the step page {string} says {string}", (_ctx, path: string, text: string) => {
        expect(page(`book-1/${path}`)).toContain(text);
      });
    });
  });
~~~
