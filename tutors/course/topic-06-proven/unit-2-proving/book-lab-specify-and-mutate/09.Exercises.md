# Exercises

## Exercise 1: an equivalent mutant

`course-builder.ts` keeps a survivor: `IGNORED = new Set(["json", "html", "node_modules"])` mutated to
`new Set([])`. Find a course folder for which the two versions build different courses. If you cannot,
the mutant is *equivalent*: explain which other line already does the set's job, and decide whether to
delete the set. A deletion is a refactor: which tests must stay green?

## Exercise 2: paragraph breaks

`markdown.ts` has survivors on `startsBlock`, such as `const startsBlock = () => undefined`. Write the
smallest unit test in `tests/unit/lite/markdown.test.ts` that kills them. Hint: a paragraph line followed
straight away, with no blank line, by a heading. Run `pnpm test:mutation` and `pnpm check:mutation-floors`.
You should meet a `stale-floor` finding. What does it ask for, and why is a floor that is never raised a
risk?

## Exercise 3: a property for R-013

Add a property to `tests/fuzz/` for R-013: for every lab of one to six steps, page *i* says "Step *i* of
*n*" when *n* > 1 and nothing otherwise. Give it a "can fail" test against a broken site builder, or suite
health will fail it. Does it kill more mutants than your unit test?

## Exercise 4: upstream's blind spot?

Upstream's `vitest.config.mutation-nightly.ts` includes `tests/bdd/steps/**/*.steps.ts`. Using what you
learned in step 6, would a mutant reached only by a When step in upstream's nightly run be killed? Find one
upstream steps file whose When step does the work and whose Then step only reads the result. Write down
what you would test to find out, before you claim anything.
