# Write the sentence

The new rule: on a lab of several steps, each step page says where it is, such as "Step 2 of 3".

## Take an id

~~~bash
pnpm test:ears:audit --next-id
~~~

~~~
R-013
~~~

## Write it in EARS

It happens when a lab has more than one step, so it is Event-driven: "When ..., the site shall ...".
It is about a page, so the system is the site and the layer is lite. Add this row under `R-012` in
`REQUIREMENTS.md`:

~~~markdown
| R-013 | Event-driven | When a lab has more than one step, the site shall label each step page with its position, such as Step 2 of 3. | lite |
~~~

## The closure refuses it

~~~bash
pnpm test:ears:audit
~~~

~~~
unproved-requirement: REQUIREMENTS.md:24 R-013: no Rule tagged @R-013 has a scenario. Add one to the
feature for its layer in tests/bdd/features.
 ELIFECYCLE  Command failed with exit code 1.
~~~

A requirement without proof is a wish. `pnpm test` fails the same way, in
`tests/suite-health/requirements.test.ts`.

## Try the audit's other checks

Change your sentence to break one thing at a time, run the audit, read the message, and put it back:

| "label each step page" to "handle step pages properly" | `vague-language` |
| "the site" to "the reader" | `system-name` |
| the layer `lite` to `gen` | `layer-mismatch` |
