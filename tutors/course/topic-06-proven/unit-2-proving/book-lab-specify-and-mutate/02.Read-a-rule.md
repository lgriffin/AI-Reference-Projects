# Read a rule end to end

Follow `R-010` from its sentence to its code.

1. `REQUIREMENTS.md`: find the row. Note its pattern (Event-driven) and its layer (lite).
2. `tests/bdd/features/site/static-site.feature`: find `@R-010 @ears-event-driven`. Compare the `Rule:`
   title with the row, word by word.
3. `tests/bdd/steps/site/static-site.steps.ts`: find the `Rule("When a lab has more than one step, ...")`
   call. Each `Given`, `When` and `Then` string matches a line of the scenario; `{string}` captures the
   quoted text.
4. `packages/lite/src/site-builder.ts`: find `labPages`. Which lines make the Previous and Next links?

## Break the chain on purpose

Change one word of the `Rule:` title in the feature, for example "each step page" to "every step page".

~~~bash
pnpm test:ears:audit
~~~

~~~
rule-title-drift: tests/bdd/features/site/static-site.feature:...: the Rule's title is not R-010's
sentence. One sentence, one source: copy it from REQUIREMENTS.md:... word for word.
~~~

Run `pnpm test:bdd` too. vitest-cucumber fails as well, because the steps file binds the old title:
`FeatureUknowRuleError: Rule: When a lab has more than one step, ... does not exist`. Two checks, two
different jobs: the audit guards the sentence; vitest-cucumber guards the binding.

Undo the change and run `pnpm test` again before you go on.
