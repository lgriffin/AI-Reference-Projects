# Run a slice of upstream

Now the same machinery in tutors-mono-repo. Use the clone and the Node.js 26 you installed in Orientation
Lab 1, with its dependencies installed (`pnpm install`).

~~~bash
cd ~/src/tutors-mono-repo
~~~

## The EARS audit

~~~bash
pnpm test:ears:audit
pnpm exec tsx scripts/checks/ears-audit.ts --next-id
~~~

At commit `2b96b69` the audit prints:

~~~
OK: 85 feature file(s), 441 Rule(s), 0 new violation(s), 0 baselined, 0 stale baseline entries.
~~~

and the next free id is `0786`. Your numbers will be higher on a newer commit.

## The audit's own tests

~~~bash
pnpm exec vitest run tests/suite-health/ears-audit.test.ts
~~~

~~~
 Test Files  1 passed (1)
      Tests  25 passed (25)
~~~

Open the file. The `ROOT` constant points at `tests/suite-health/fixtures/ears-audit/root`: a fake
repository of feature files written to break the rules. Compare it with
`tests/suite-health/requirements.test.ts` in rung 5, which builds its negative fixtures from strings.

## The whole BDD tier (optional)

~~~bash
pnpm test:bdd
~~~

This needs the workspace's packages built first. If many files fail with `Failed to resolve import
"@tutors/runes"` or `Cannot find package '@tutors/data-api'`, the build is missing, not the tests: run the
single files above instead, or follow the setup in upstream's `CONTRIBUTING.md`.
